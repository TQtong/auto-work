# 阶段三 B1：Excel 安全解析与持久化预检

## 1. 本增量边界

本增量实现 XLSX 文件安全检查、三类工作表识别、单元格语义解析、Jira 候选匹配、逐行诊断和预检持久化。它关闭 `XLS-001`、`XLS-002` 的解析路径，并建立 `XLS-003` 的预检半程；导入修正、确认提交、Jira 主字段保护和逐字段 provenance 在后续 03B2 增量完成，不能因本提交存在预检接口而提前视为已验收。

## 2. 文件入口与容器安全

- `POST /api/v1/excel-imports/preview` 只接收单个 multipart 文件，文件上限 8 MiB，拒绝附加字段、多文件和超出限制的请求。
- 文件名必须是无路径、无控制字符的 `.xlsx` 名称；MIME 类型必须属于允许集合，文件内容还必须具有真实 ZIP 签名。
- 使用 ZIP 中央目录检查最多 2,000 个条目、64 MiB 总解压大小和单条目 200 倍压缩比，拒绝加密条目、宏项目和宏启用内容类型。
- 必须存在 `[Content_Types].xml`、工作簿和根关系入口；外部链接与数据连接只形成 warning，不加载、不刷新、不计算外部内容。
- 原文件字节、上传路径和服务器临时路径均不写入数据库。解析失败只保存 SHA-256、展示文件名、错误码和净化摘要。

## 3. 工作簿语义解析

- 精确识别 `后端开发jira`、`前端开发jira`、`系统测试jira`，也支持 A:G 语义表头识别；H 可无标题或不存在。
- 限制最多 20 个工作表、每表 10,000 行、64 列和总计 100,000 个单元格，避免超大工作簿拖垮本机进程。
- 每个使用过的单元格保留地址、原始类型、原值、公式、缓存结果和数字格式；额外列只记录为 ignored，不静默进入任务字段。
- A/B 同空时只继承当前工作表最近的有效父任务；半空标记 conflict；C/D 同空识别为父容器；仅 C 有值允许未分配 warning；仅 D 有值 blocking。
- 日期支持 Excel 日期类型、1900/1904 序列系统、公式缓存和严格年月日字符串；歧义字符串、缺失公式缓存、越界日期及结束早于开始均阻断，不猜测本地日期。
- G 为空时工时和人日均为 `null`，即使 H 缓存为 0；G=0 保留明确零语义。H 只用于校验，系统按用户的 `workdayHours` 计算人日并记录换算信息。
- 经办人只与已确认身份别名匹配。样表姓名不会被硬编码为当前用户。

## 4. 匹配、幂等与持久化

- Jira 自动链接必须同时满足父 issue key、规范化标题和经办人且候选唯一；多候选进入 conflict，模糊相似不会静默合并。
- 每行生成稳定指纹，预检保存原始字段、继承字段、规范化结果、诊断、候选、建议动作和匹配任务。
- 文件 SHA-256 与解析器版本构成唯一预检键。同一字节文件重复上传返回原预检，不重复生成导入或行记录。
- `GET /api/v1/excel-imports` 提供预检历史，`GET /api/v1/excel-imports/:id` 返回逐行详情；文件内容仍不会从这些接口返回。

## 5. 数据模型与迁移

- `ExcelImport` 保存文件事实、解析器版本、工作表清单、统计、状态、错误摘要和版本。
- `ExcelImportRow` 保存工作表坐标、行类型、原始/继承/规范化 JSON、稳定指纹、候选、诊断、动作和可选任务引用。
- `TaskFieldProvenance` 在本迁移中先建立完整约束与关联，供 03B2 的单事务提交和 Jira 后续覆盖保护使用；本增量不写伪 provenance。
- 从全新 SQLite 数据库应用全部 6 个生产迁移后，`prisma migrate status` 为最新，schema diff 为零，`PRAGMA integrity_check=ok`，外键违规为 0。

## 6. 自动化验证

`excel-import-parser.spec.ts` 覆盖：

- 三表等价样例、父任务继承、父容器、G 空/H=0、G/8 公式与原始单元格保存；
- 1904 日期系统、公式无缓存、半空父任务、歧义日期；
- 非法文件名、伪 XLSX、宏条目、宏内容类型和高压缩比 ZIP。

`excel-import-preview.integration.spec.ts` 从空库应用全部生产迁移，覆盖：

- 唯一 Jira 候选链接、Excel 新任务建议、原始/公式事实持久化；
- 相同哈希与解析器版本重放，导入和行均不重复；
- 损坏文件只保留哈希与净化错误摘要。

全仓 `pnpm verify` 通过：格式检查、lint、类型检查、101 项测试和生产构建均成功。其中 API 21 个测试文件共 82 项全部通过。
