# 阶段四 B2b：AI 建议工作流、人工决定与确定性回退

本增量把 04B1 的三协议供应商端口和 04B2a 的白名单净化/不可变留痕内核接入完整周报工作流。AI 只能基于当前冻结版本生成独立建议；成功结果不会自动覆盖正文，失败、安全阻断或输出不合格也不会阻止用户继续编辑。采纳和拒绝都是显式、带原因、幂等且可审计的人工决定。

## API 与并发契约

- `POST /weekly-reports/:id/ai-suggestions`：提交基线版本 ID、周报聚合版本、健康 AI 连接、建议栏位和三个独立条件同意开关。接口要求 `Idempotency-Key`，严格拒绝额外字段和重复栏位。
- `GET /weekly-reports/:id/ai-generations`：返回最近 100 次生成摘要，并通过独立计数返回完整历史总数；摘要不返回供应商原始输出。
- `GET /weekly-reports/:id/ai-generations/:generationId`：返回净化引用、哈希、配置/提示词/策略版本、供应商请求事实、usage、解析结果和按纯文本处理的原始输出，不存在凭证字段。
- `POST /weekly-reports/:id/ai-generations/:generationId/adopt`：同时校验建议版本、生成基线、当前版本和周报聚合版本。成功后新建 `origin=manual` 的人工派生版本、复制来源链接、切换当前指针，并使旧确认/交付状态失效。
- `POST /weekly-reports/:id/ai-generations/:generationId/reject`：记录非空人工原因并冻结拒绝决定，不修改当前正文。
- AI 建议生成、采纳和拒绝均走已有幂等记录与审计管道。并发编辑导致基线变化时返回稳定冲突码；旧建议禁止采纳但仍允许明确拒绝，避免遗留永久待决定记录。

## 从净化到供应商调用

生成顺序固定为：

1. 校验当前用户拥有周报、基线版本和聚合版本均未变化；
2. 只从冻结来源快照重建 04B2a 白名单对象；
3. 在本机执行秘密、源码、diff、客户高敏和条件同意检查；
4. 用保守 token 估算与连接的 `maxInputTokens` 比较；
5. 仅在前述检查全部通过后，才从 DPAPI 凭证库读取连接密钥；
6. 调用 04B1 统一三协议客户端；
7. 对原始输出再次执行秘密/主动内容扫描，再进行严格 JSON、schema、引用与事实校验；
8. 成功时在一个事务中写入结束态生成记录、AI 建议版本、逐栏位来源链接、审计和幂等结果。

输入命中秘密时，供应商凭证不会读取、网络端口不会调用，生成记录只保留阻断类别。供应商输出若试图返回 Authorization、token、源码或主动内容，同样在本机阻断，且危险原文既不写入 `rawOutput`，也不进入响应或审计。

## 独立建议与确定性回退

- 成功生成会预留新的周报聚合版本号并创建不可变 `origin=ai` 建议，但 `currentVersionId` 保持原基线；页面因此可同时展示当前正文和建议差异。
- 供应商 401/403/429/5xx、连接失败、无效 JSON、缺栏位、未知引用、数字/日期/issue key/项目漂移、token 超限和安全阻断均产生稳定结果，不把半成品写成成功建议。
- 可记录的调用失败会落一条 `failed` 或 `blocked` 生成事实，响应返回当前规则/人工版本作为 `fallbackVersion`。连接不存在、不健康、用途不允许等请求前置错误会直接拒绝，不伪装成模型尝试。
- 采纳不会更新或删除 AI 原建议，而是新建人工派生版本；拒绝只改变一次性人工决定。数据库触发器保证生成事实不可篡改、决定只能从 `pending` 单向结束。

## 周报工作台

“AI 建议与依据”抽屉提供完整操作面：

- 只列出支持周报用途的 AI 连接，并把非健康连接禁用；五个正文栏位默认选中，人员姓名、内部 URL 和 Jira 描述摘要三个同意开关默认全部关闭。
- 页面持续展示数据边界、秘密扫描发生在凭证读取前、规则/人工版本始终是回退基线等安全说明。
- 历史卡片同时显示生成状态、人工决定、是否基线过期、建议版本、协议/模型、耗时、范围、错误码和安全类别，不只依赖颜色表达状态。
- 详情展示配置版本、prompt 版本、净化策略版本、留存方式、净化输入哈希、供应商请求 ID、停止原因、usage、移除类别和本地引用映射。
- 解析建议按栏位、项目、段落和 citation 标签展示；供应商原始输出始终放在 React 转义的 `<pre>` 中，不使用 Markdown、HTML 注入或 `dangerouslySetInnerHTML`。
- 用户可逐字段比较 AI 建议与当前版本。采纳/拒绝均弹出二次确认和非空人工原因；过期建议的采纳按钮禁用，拒绝仍可执行。

## 自动化与可见页面验收

- 请求契约测试 5 项：默认关闭条件同意、栏位去重、严格字段白名单、采纳并发坐标与人工原因、拒绝原因与额外字段拒绝。
- AI 策略测试 19 项、持久化集成测试 3 项、工作流集成测试 6 项，共 33 项针对性测试通过。工作流覆盖成功非当前建议、显式采纳、供应商失败回退、非法输出回退、危险供应商输出不落库、输入秘密在凭证读取前阻断、过期采纳拒绝、拒绝结束态和详情无凭证。
- 全仓 `pnpm verify` 通过：Contracts 2 项、Domain 28 项、API 155 项、Web 9 项测试全部通过，同时通过 Prettier、全仓 ESLint、TypeScript 类型检查和生产构建。
- 本机可见页面以 1280×900 视口验收：1040 像素 AI 抽屉无横向溢出；五个建议栏位默认选中、三个条件同意默认关闭；无健康连接时生成按钮禁用；成功建议的详情、引用、纯文本原始输出、逐字段比较以及采纳/拒绝二次确认均可操作；页面控制台日志为空。
- 可见页面的成功建议使用明确标记为“QA 界面验收 AI（非外部 UAT）”的本机事务夹具，验收后已精确删除并恢复周报聚合版本。它只验证 UI 与 API 读路径，不冒充真实供应商联调。

## 验收状态与外部边界

04B2b 的本机工作流、异常、安全和可见页面矩阵已达到 `verified`。`AC-AI-02` 的不可绕过数据边界和 `AC-AI-03` 的无工具/无最终决定权已有自动化与页面证据；`AC-WRP-03` 的 AI/人工/快照版本链已实现，但整项仍需结合后续钉钉交付闭环复核。

仓库没有用户授权的真实 OpenAI-compatible、Anthropic 或 Gemini 凭证，因此本增量没有向外部供应商发送测试请求，也不把协议桩或本机夹具描述成企业 UAT。04B1 的协议实现、真实连接测试端点和错误映射已存在；有授权连接后仍需分别执行三协议真实探测与生成回归，才能把 `AC-AI-01` 提升为最终外部验收完成。
