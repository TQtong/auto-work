# 阶段四 C1：钉钉正式日志与加签机器人能力探测

## 1. 本增量边界

04C1 完成钉钉正式日志和自定义机器人的真实协议适配、能力探测、模板/收件人事实冻结，以及机器人凭证的显式测试轮换。状态为 `implemented`：固定接口契约、安全与持久化恢复矩阵已自动验证；当前工作区没有用户授权的钉钉测试企业、应用凭证和专用测试群，因此没有把 fixture 描述成企业环境联调成功。

正式日志创建与结果查询、机器人短摘要、双通道幂等、计划任务、`unknown` 恢复、部分交付和降级复制属于 04C2/04C3。04C 完整交付前，`DNG-001/002/003` 不提升为 `verified`。

## 2. 固定主机与双协议隔离

- 企业应用令牌固定调用 `POST https://api.dingtalk.com/v1.0/oauth2/accessToken`，仅发送 App Key/App Secret；令牌以内存哈希键缓存并在过期前提前刷新，数据库不保存自动获取的令牌。
- 正式日志当前批准适配器固定使用 `https://oapi.dingtalk.com`，模板探测调用 `/topapi/report/template/getbyname`。配置和调用阶段都拒绝自定义主机、端口、路径、查询参数、URL 凭证、片段、私网和本机地址。
- 加签机器人只接受 `https://oapi.dingtalk.com/robot/send?access_token=...`，并要求唯一 `access_token` 参数；签名严格使用 `timestamp + "\n" + secret` 的 HMAC-SHA256 Base64 结果。
- 正式日志与机器人具有独立连接类型、能力和后续交付状态。机器人能力明确记录 `fullReportForbidden=true`，不得在日志不可用时冒充正式提交。

协议与安全设置按 2026-07-18 的[钉钉开放平台](https://open.dingtalk.com/)和[自定义机器人文档](https://open.dingtalk.com/document/orgapp/custom-robot-access)核对；企业内应用权限、模板和群仍必须由用户在专用环境显式联调。

## 3. 正式日志模板与收件人事实

- 日志连接新增必填的操作用户 User ID；探测同时校验返回模板所属用户和模板名称，避免跨用户或同名结果误绑定。
- 探测响应必须恰好包含六个唯一字段。能力快照冻结模板 ID/名称、模板哈希、字段名称/类型/顺序/必填/maxLength、操作用户、默认用户/群、供应商 request ID、观察与过期时间。
- 当前模板接口没有返回可依赖的稳定字段 ID、必填和长度语义，因此适配器以顺序、名称和类型生成可重复的合成字段 ID，并显式标记“所有观察字段按创建必填处理”和 `maxLength=null`，不伪造供应商限制。
- 模板映射保存不再只比对一个快照哈希，而是逐项核对模板标识、观察/过期时间及六字段事实；任一字段被手工改名、改类型、改顺序或改限制都会拒绝。
- 默认接收用户和群以不可变验证记录持久化，有效期 24 小时；重新探测发现对象已移除时立即追加不可用事实，不能继续沿用仍在有效期内的旧缓存。后续确认/提交只能使用未过期的同连接事实。
- 已批准适配器当前明确报告通用附件能力不受支持。04C2 在正式创建前必须阻断附件交付并提供清楚的复制/导出降级，不能静默丢附件。

## 4. 机器人显式测试与安全轮换

- 创建或替换 Webhook/Secret 时只写入 DPAPI 保险箱的待测试槽位，不自动发群消息、不覆盖当前凭证，也不改变已有健康状态。
- 设置页对真实外部副作用增加二次确认；探测只发送固定文本，明确说明仅验证 Webhook 与加签，不包含周报正文、凭证或本机链接。
- 钉钉确认接收后，后台以连接版本和待测试引用为并发条件，原子提升新凭证、清空待测试槽位、更新能力和成功时间；数据库成功后才删除旧保险箱引用。
- 测试失败时保留旧凭证、旧健康状态和待测试凭证，并只附加净化后的失败分类与时间，允许用户修正后重试。并发期间配置变化则拒绝替换。
- 同一凭证处于排队/执行状态时使用稳定哈希去重，机器人测试最多执行一次；测试处理器采用 `manual_review` 崩溃恢复，避免“消息已送达、数据库尚未落状态”时自动重发。
- 撤销凭证会同时清除当前和待测试引用。API/页面只暴露掩码、待测试布尔值和创建时间，不返回任一保险箱引用或秘密。

## 5. 自动化证据

- 供应商契约测试覆盖新版令牌端点、缓存、固定日志主机、模板用户/名称校验、机器人精确签名与正文结构。
- 安全负向测试覆盖伪造主机、额外查询参数和超长机器人文本；探测测试覆盖六字段、模板能力、收件人快照和固定无敏感消息。
- SQLite 集成测试覆盖机器人创建/替换不探测、成功原子提升与旧凭证删除、失败保留当前健康凭证和待测试引用。
- 模板映射集成测试覆盖快照伪造、外部字段事实伪造、错序字段、不可变版本和连接类型门禁。
- 设置页视图模型测试覆盖日志操作用户、固定主机、应用凭证，以及机器人普通配置与一次性秘密分离。
- 全仓 `pnpm verify` 通过：Contracts 2、Domain 28、API 166、Web 11，共 207 个测试；Prettier、ESLint、TypeScript 类型检查和 API/Web 生产构建全部成功。Prisma schema 有效，13 个迁移已部署且状态一致。

## 6. 浏览器验收

在 2026-07-18 的本机 API/Vite 实例和 1280 像素宽视口完成真实页面交互：正式日志表单会自动写入并锁定官方 `oapi.dingtalk.com` 地址，操作用户字段和权限说明可见；机器人表单明确显示“保存不发消息”和待测试提升规则。临时待测试机器人行正确区分“当前凭证未配置/待测试凭证已安全保存”，测试与撤销按钮均可用；点击测试只打开包含固定消息边界的二次确认，验收未点击确认、未调用任何钉钉地址。页面 `documentWidth=1265`、`viewportWidth=1280`，无横向溢出。验收记录、待测试引用及本机服务进程均已精确清理。

## 7. 下一增量

04C2 将实现只接受已确认版本的正式日志创建、外部报告 ID 与请求事实持久化、双通道独立幂等、机器人短摘要和安全链接；04C3 将实现可查询结果恢复、`unknown/needs_review`、429/5xx 有界重试、计划任务、部分交付、附件能力阻断/清理和复制导出降级。未经授权的企业凭证联调仍不会被自动执行或伪造为成功。
