# 阶段五 D5：任务中心完整性终审增量

## 1. 终审发现

逐条核对 `docs/detailed-design/05-task-sync-excel-evidence-design.md`、`08-http-api-contracts.md` 和 `09-frontend-ux-design.md` 后，确认原任务中心并非完整交付，存在以下缺口：

1. API 缺少项目、Jira 原始状态、父任务、Sprint 和字段冲突等组合筛选；
2. 页面只覆盖部分筛选，不能在列表和父任务分组间完整切换；
3. 人工字段覆盖只有设计，没有字段白名单、原因、有效期、乐观锁、冲突清单、到期/撤销恢复和审计闭环；
4. 任务列表没有逐字段来源标签，不能并列查看人工值和 Jira 最新值；
5. 任务详情没有设计要求的六个页签，也没有周报段落引用和季度成果引用。

本增量逐项补齐上述缺口，没有用静态标签或前端模拟状态代替数据库事实。

## 2. 完整筛选、分页与分组

- `GET /tasks` 现支持项目、统一/原始状态、父任务 Key、Sprint ID/名称、到期日区间、来源、当前用户、Jira 连接、证据状态、冲突和可见性组合筛选；未知参数由严格 schema 拒绝；
- Sprint 仍以 JSON 持久化，但查询使用带 JSON 引号的完整值，`12` 不会误命中 `112`；
- 页面所有筛选均进入服务端游标查询，筛选变化会清空旧游标，上一页/下一页不会混用其他条件的游标；
- 列表和父任务分组共享同一批服务端事实；无父任务项明确进入“无父任务”组；
- 每项显示计划开始、到期日和原始预估的当前来源，人工/Jira 冲突使用红色标签和冲突数量。

对应提交：`60da16f`、`fa27d85`。

## 3. 人工覆盖与冲突生命周期

- 白名单仅允许 `plannedStartDate`、`dueDate`、`originalEstimateSeconds`；日期、非负整数秒、原因和未来 366 天内有效期均由服务端再次校验；
- 每次写入携带任务 `version`，最终 SQL 更新条件实施乐观锁，旧页面不能覆盖新事实；
- 生效覆盖保留本地展示值，但 Jira 继续同步。Jira 新值与人工值不同时，保存最新 Jira 值、检测时间并进入冲突清单，不会静默覆盖任一侧；
- 撤销恢复最新 Jira/Excel 来源事实；60 秒调度收敛到期覆盖，两个路径都创建新的来源记录并保留人工历史；
- 设置、撤销和系统到期均写非敏感审计；接口返回冲突游标、总数和任务版本；
- 页面提供覆盖/调整、原因、有效期、撤销原因、并列冲突卡片和冲突筛选，并同步失效任务摘要、详情和冲突缓存。

数据库迁移 `20260719090000_task_manual_override_lifecycle` 为 provenance 增加有效期、冲突值、检测时间及索引。对应提交：`2362d48`、`e7c5c7e`。

## 4. 六页签详情与报告回看

任务详情现在严格分为：

1. 概览：只读任务事实、本地覆盖、当前来源和有效期；
2. 来源与字段：逐字段不可变来源历史、合并决定、生效/失效时间；
3. 证据：Git/GitLab 证据建议、人工绑定和决定生命周期；
4. 状态观测：状态变化区间及来源观测；
5. 周报引用：真实 `ReportSourceLink`，展示周期、不可变版本、当前/已确认双标志、字段、段落、冻结摘要和引用时间；
6. 绩效引用：真实 `AchievementEvidence`，展示季度评审、成果选择/材料状态、主证据、可用性、贡献角度和引用时间。

引用查询限定当前本机用户，测试同时插入另一用户的周报和季度材料，确认不会串读。周报和季度名称提供深链，目标工作台读取 `reportId/reviewId` 并优先选中被引用对象；无引用时显示明确空态。

对应提交：`c28299f`、`557020c`。
