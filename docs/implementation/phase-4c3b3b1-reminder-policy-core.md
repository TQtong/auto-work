# 阶段四 C3b3b1：周报提醒策略与 Asia/Shanghai 计划内核

## 1. 状态与范围

04C3b3b1 已完成可持久化、可审计的周报提醒策略，纯领域计划计算、配置 API 和设置页面形成完整闭环，状态为 `verified`。本增量只负责“配置什么、何时发生”和未来计划预览；后台滚动计划、休眠补发、超时 `skipped` 及实际机器人通知由紧接的 04C3b3b2 实现，不把尚未运行的调度描述为已发送。

策略默认 `enabled=false`，保存设置本身不会发送机器人消息，不会生成、确认或正式提交周报。

## 2. 完整策略模型

每个本机用户最多一条 `weekly_report_reminder_policy`，包含：

- 固定业务时区 `Asia/Shanghai`；
- 1–7 的不重复工作星期；
- 生成提醒、确认提醒、截止提醒各自的启用状态、工作星期和 `HH:mm` 时刻；
- 休眠恢复宽限 0–1440 分钟；
- 可空机器人连接和策略总开关；
- 乐观锁版本、创建/更新时间。

默认工作周为周一至周五，三类提醒预置为周五 14:00、16:00、17:30，宽限 120 分钟。预置并不等于启用，避免升级后意外向企业群外发。

数据库外键只引用机器人连接，不复制 Webhook 或 Secret。触发器继续约束时区、星期、时刻、宽限、版本严格递增以及“启用时必须有机器人”。API 还验证工作星期唯一、至少启用一种提醒及三类启用提醒严格按时间递增。

## 3. 确定性时间计算

`@auto-work/domain` 新增纯函数计划计算器：

- 以 Asia/Shanghai 自然周定位周一，再按用户工作星期确定周期起止与填写日期；
- 本地 `HH:mm` 明确转换为 UTC `Date`，队列和数据库不保存歧义本地时间；
- 每条计划生成稳定周期键、提醒类型、周期、报告日期、计划时间和宽限截止；
- 可连续生成 1–53 周，结果按绝对时间稳定排序；
- 非上海时区、无效工作周、无效时刻、倒置/相同时刻和非法宽限均抛出稳定领域错误。

这套计算不依赖系统当前时区。2026-07-17 周五 14:00/16:00/17:30（上海）分别固定为 06:00/08:00/09:30 UTC。

## 4. API、安全门禁与审计

- `GET /weekly-reports/reminder-policy`：未保存时返回完整但不落库的安全默认值，并预览未来六个时刻。
- `PUT /weekly-reports/reminder-policy`：要求版本号；首建使用版本 0，后续必须匹配当前乐观锁版本。
- 启用策略时机器人必须是已启用、测试健康、存在当前凭证且没有待启用凭证的 `dingtalk_robot`；无效连接在策略写入前拒绝。
- 创建/更新与审计同事务完成。审计只哈希记录机器人 ID、工作周、时刻、宽限和版本，不接触机器人凭证。

## 5. 设置页面

“设置与集成”新增独立“周报提醒”页签：

- 选择健康机器人、策略总开关、工作星期和宽限分钟；
- 三张卡片分别配置生成/确认/截止提醒的启用、星期和时刻；
- 页面明确保存不会发消息，提醒不会自动生成、确认或正式提交；
- 展示未来计划的类型、周期、计划时间和补发截止，便于保存前后核对时区语义；
- 客户端先做必填和格式提示，服务端领域校验仍是不可绕过的边界。
