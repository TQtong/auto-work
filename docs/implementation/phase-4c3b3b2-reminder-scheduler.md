# 阶段四 C3b3b2：提醒滚动调度、休眠恢复与运行账本

## 1. 状态与安全边界

04C3b3b2 已把提醒策略接入持久化调度、通用作业队列、机器人通知账本和设置页运行记录，状态为 `verified`。系统只发送固定的生成提醒、确认提醒和截止提醒，不会自动生成、自动确认或正式提交周报；正式日志仍受独立的显式批准与执行前门禁保护。

调度只在当前实例持有单实例租约时运行。应用启动时立即核对一次，之后每 30 秒核对；策略默认关闭，因此升级和保存默认配置不会产生任何外部消息。

## 2. 持久化 occurrence 与滚动计划

第 20 个迁移新增 `weekly_report_reminder_occurrence`。每条 occurrence 冻结以下业务事实：

- 策略 ID、策略版本、提醒类型和稳定周期键；
- 周报周期起止日、填报日、计划 UTC 时间和宽限截止时间；
- `planned / queued / succeeded / failed / unknown / skipped / cancelled` 状态；
- 可空的周报、通知和作业关联，以及排队、跳过、完成、错误和乐观锁事实。

数据库用“策略 + 策略版本 + 周期 + 提醒类型”复合唯一键阻止重启或并发轮询重复建账，并用触发器约束类型、状态、时间、终态和版本单调递增。每轮补齐当前周及未来八周；只查询缺失键后创建，SQLite 不支持 `createMany.skipDuplicates` 时再由唯一键收敛竞态。

迁移同时把 `robot_notification.report_id` 调整为可空，因为生成提醒可能早于周报实体存在。迁移采用重建表方式并逐列复制既有通知事实，重新建立全部唯一键、索引、外键和校验触发器，没有用清空旧数据规避兼容问题。

## 3. 到期、休眠恢复与跳过语义

到期 occurrence 按计划时间和创建时间稳定排序处理：

- 当前时间仍在宽限内时，只创建一次通知账本和一次通用 Job；Job 立即排队，但消息事实仍保留原计划时间；
- 当前时间晚于计划时间但仍在宽限内时，审计与安全的 Job 摘要标记 `recoveredAfterSleep=true`，用于证明这是休眠恢复补发；
- 当前时间超过宽限时，不创建 Job、不调用机器人，通知账本和 occurrence 同事务写入 `skipped / MISSED_GRACE_WINDOW`；
- 生成提醒发现本周期已有周报、确认提醒发现已确认或已提交、截止提醒发现已提交时，同样以明确原因写入 `skipped`，不伪造发送；
- 单条 occurrence 处理失败只记录中文日志并继续处理其他到期项，下一轮仍可依据 `planned` 状态恢复。

长期休眠不依赖内存计时器历史。恢复时重新生成当前周计划并使用数据库绝对时间判断“补发还是跳过”，因此重启、系统睡眠和进程中断使用同一套确定性规则。

## 4. 策略变化、取消和并发收敛

策略更新会递增版本，并在保存策略的同一事务中取消旧版本的 `planned / queued` occurrence、未发送通知和仍排队 Job。停用策略使用相同路径。调度轮询还会兜底清理漏网的旧版本计划。

已经进入 `sending` 的通知不会被伪装为已撤销；其结果继续由通知 handler 或作业租约恢复逻辑落为 `succeeded / failed / unknown`。通知 handler 完成外部调用时，会原子同步 occurrence 的终态；应用崩溃导致作业租约过期时，Job、通知和 occurrence 一起落为 `unknown`，交由现有人工核对流程处理，而不是自动重发可能已经送达的消息。

## 5. 固定安全消息与页面可见性

- 生成提醒只说明周期尚需准备，并明确“不会自动生成或正式提交”。
- 确认提醒携带当前草稿状态，并明确“不会自动确认或正式提交”。
- 截止提醒显示 Asia/Shanghai 截止时刻和当前草稿状态，不包含完整周报正文。
- 三类提醒继续复用机器人静默窗口、内容哈希、状态版本去重、供应商调用证据和敏感信息脱敏。

提醒策略 API 现在返回最近 occurrence。设置页新增“提醒运行记录”，展示提醒类型、策略版本、周期、计划时间、状态、跳过原因和错误码；周报通知列表也能区分三类提醒。用户可以从页面判断计划是否补发、跳过、取消或进入未知状态，不需要读取数据库。

- 迁移测试先在第 19 个迁移结构中写入旧通知，再执行第 20 个迁移，验证冻结字段完整保留且 `PRAGMA foreign_key_check` 为空。

- 超出宽限测试验证 occurrence 和通知均为 `skipped`，Job 数量及外部调用次数均为零。
- 策略更新测试验证保存事务立即取消旧 occurrence、通知与 Job；状态满足的三类提醒测试分别验证跳过或安全发送。
