# 阶段四 A2：周报来源快照与不可变规则版本

## 1. 当前增量状态

本增量把 04A1 的确定性规则接入生产数据库和 HTTP API，完成默认工作周、版本化企业工作日历、来源新鲜度策略、原子来源快照、不可变规则版本、段落级来源链接、同周期冲突和稳定重放。04A2 状态为 `implemented`；人工编辑/恢复/确认状态机和真实页面验收将在 04A3 独立完成，因此阶段四仍不能标为 `verified`。

## 2. 版本化工作日历

- `WorkCalendar` 只保存当前生效版本指针和聚合版本；`WorkCalendarVersion` 保存时区、工作星期、逐日覆盖、来源和内容哈希，历史正文不原地修改。
- `GET /api/v1/settings/work-calendar` 返回当前版本和最多 100 条历史；`POST /api/v1/settings/work-calendar/versions` 创建并激活新版本，同时写审计。
- 星期和逐日覆盖规范化排序后再计算哈希；重复星期、重复日期、非法业务日期和非上海时区在写入前阻断。
- 当前版本内容完全相同时稳定重放；若用户恢复某个旧版本的相同内容，仍创建新的版本号并切换指针，保留真实变更历史。
- 默认周期取 Asia/Shanghai 当前自然周中的首末工作日，填写日期取最后一个工作日；没有企业日历时回退周一至周五并在周报中保留明确 warning。

## 3. 周报聚合与不可变历史

- `WeeklyReport` 是聚合根，分别保存编辑状态、日志交付子状态、机器人交付子状态、当前版本、确认版本、接收范围版本和乐观版本。
- `ReportSourceSnapshot` 冻结周期、时区、日历版本、当前用户身份版本、Jira 查询条件和成功同步运行、任务/证据/人工白名单事实、新鲜度策略、规则版本、模板映射版本及 AI 净化策略版本。
- `WeeklyReportVersion` 以纯文本和结构化段落 JSON 同时保存固定六字段，保存来源快照、父版本、来源类型、内容哈希和变更摘要；规则版本只追加，不原地覆盖。
- `ReportSourceLink` 细化到 `version + field + block + source`，保存任务、证据或人工来源的当时摘要和内容哈希，使页面能够从任一段落回看原始事实。
- SQLite 直接约束日历时区/版本、周报状态与交付子状态、版本来源、问题字段非空、字段名、来源类型及 task/evidence 引用一致性；不可变正文表设置 UPDATE 阻断触发器。

## 4. 来源收集与新鲜度

- 只收集当前用户且仍可见的任务；快照字段使用明确白名单，不读取或保存 Jira description、源码、diff、环境变量、密钥和附件。
- 任务新鲜度由最后观测时间和关联同步运行状态共同判断；证据新鲜度由来源可用性和最近同步时间共同判断。
- `require_fresh` 是默认策略：任一任务/证据过期或不可用时拒绝生成且不产生报告；用户明确选择 `allow_stale` 后才继续，并把风险固定到快照和版本 warning。
- 已确认关系进入确定性正文。只有用户明确启用 `includeUnconfirmedEvidence` 时，待确认关系才进入快照；同项目、周期内且作者命中已验证 Git 姓名/邮箱别名的未关联 Commit 也只作为待确认候选，不擅自绑定任务或写入正文。
- 人工输入必须带稳定来源 ID；重复来源 ID、空内容和非法字段均被拒绝，保证来源链接和重放哈希稳定。

## 5. 生成、冲突与查询 API

**`POST /api/v1/weekly-reports/generate`** 返回 202，并在同一 SQLite 事务中完成：

1. 解析显式周期或依据日历计算默认周期；
2. 收集、净化并冻结任务、证据和人工事实；
3. 运行 04A1 确定性规则；
4. 创建周报根、来源快照、不可变规则版本和全部段落来源链接；
5. 条件更新当前版本指针并写非敏感审计摘要。

同一用户和周期默认返回 `WEEKLY_REPORT_PERIOD_EXISTS`，不会静默覆盖。调用方明确使用 `existingReportPolicy=create_version` 时才基于新快照产生父子版本；相同来源与规则哈希重复调用返回原快照和版本，不增加历史或审计。并发周期/版本唯一冲突统一收敛为 409 刷新提示，不暴露数据库异常。

已实现查询：

- `GET /api/v1/weekly-reports`：按周期、状态分页；
- `GET /api/v1/weekly-reports/:id`：聚合状态、当前/确认版本、版本数量和双通道交付摘要；
- `GET /api/v1/weekly-reports/:id/versions`：不可变版本摘要；
- `GET /api/v1/weekly-reports/:id/versions/:versionId`：完整六字段、结构化块、warning、来源快照、段落来源和变更摘要。

所有查询均限制为当前本机用户的未归档报告。AI provider 非空时明确返回“尚未启用 AI 表述”，不会伪造 AI 版本；AI 三协议将在独立增量实现。

## 6. 自动化与迁移证据

`weekly-report-snapshot.integration.spec.ts` 从空库应用全部生产迁移，覆盖 7 组场景：

1. 日历节假日/补班覆盖、相同当前版本重放、旧内容恢复为新版本和默认周期；
2. 来源、规则版本、六字段和段落链接原子生成，源任务变化后历史仍可复现；
3. 严格新鲜度阻断和显式使用 stale 来源的 warning 固化；
4. 同周期冲突、明确新版本、父子关系及相同来源稳定重放；
5. 列表、聚合、版本和来源查询的所有权边界；
6. 半套周期、重复人工来源和未启用 AI 的负向门禁；
7. SQLite 非法状态、非法版本来源、不一致来源引用及重复工作星期约束。

全新 SQLite 数据库已通过 9 条生产迁移部署，迁移状态为最新，Prisma schema diff 为零，`integrity_check=ok`，外键违规为 0。全仓 `pnpm verify` 通过：contracts 2、domain 28、API 107、Web 5，合计 142 个测试；Prettier、ESLint、TypeScript 类型检查和 API/Web 生产构建全部成功。
