# 阶段五 A2：季度多来源候选、成果证据与指标映射

## 1. 状态与边界

05A2 已完成季度来源收集、不可变快照、候选聚类、人工成果、选择/排除/恢复、证据治理、成果指标映射和材料完整性检查，状态为 `verified`。本增量没有把后续自评 AI、最终确认、Excel/Word 导出或完整绩效工作台描述为完成；也没有按 Commit、MR、代码行数或工时推断绩效价值和用户分数。

## 2. 多来源纳入规则

后台作业按 `Asia/Shanghai` 的 `[periodStart 00:00, nextPeriodStart 00:00)` 收集以下事实：

- 当前用户可见且在周期内有明确 `done` 状态迁移的 Jira/Excel 统一任务；仅 `updatedAt` 落在季度内不会入选。
- 周期内存在已确认任务—证据关系的推进任务；Commit、MR、Pipeline、Tag、Release 等证据保留原类型、外部键、URL、发生时间、可用性和内容哈希。
- 未关联任务的 Commit 只在已启用且已确认的 Git name/email 别名命中、项目启用且仓库已进入确认白名单时入选。
- 未关联任务的 MR 只在已启用且已确认的 GitLab user ID/username 命中作者或参与人、项目和仓库白名单有效时入选。设置页和 Profile API 已增加两类 GitLab 身份别名。
- 仅使用周报的 `confirmedVersionId`；草稿版本不会成为季度正式来源。
- Jira/Excel 工时连同 active provenance 来源冻结到任务事实，但候选影响字段明确声明工时高低不代表价值。
- 人工成果使用独立 `manual` 来源，可添加本地/外部链接和贡献角度；链接内容不会自动进入 AI 输入。

来源开关分别控制完成任务、证据和已确认周报。测试证明 evidence-only 不会混入纯完成任务，tasks-only 不会混入仅证据推进任务。周期边界恰好等于下一周期开始的事件被排除，季度最后一个有效瞬间被纳入。

## 3. 不可变快照、完整性与恢复

`quarterly-review.collect` 是并发度为 1、`safe_replay` 的持久化后台作业。排队响应为 HTTP 202，同一评审/版本使用稳定 dedupe key；快照按来源内容哈希与生成哈希幂等。

每个快照冻结：来源选择、新鲜度策略、任务和工时来源事实、关系证据、身份别名 ID/类型/值哈希/确认时间、已确认周报事实、警告和两个内容哈希。API 可列出快照摘要并读取指定快照的完整冻结事实，数据库触发器禁止原地更新。

完整性清单区分：

- 任务/证据过期、证据不可用；
- 未找到可纳入任务、证据或已确认周报；
- 缺少已确认身份别名、身份证据位于未确认仓库之外；
- Jira 任务字段映射未知；
- 已选成果证据覆盖、必填指标覆盖、评分理由覆盖；
- 已选成果缺证据/缺指标、必填指标缺口和重复证据引用。

`require_fresh` 遇到过期或不可用来源时进入 `collection_failed` 并留下哈希化审计；`allow_stale` 保留候选且把风险固定到快照。排队取消和运行中取消都会恢复进入 `collecting` 前的业务阶段；安全重试耗尽或不可重试失败通过通用作业终态回调退出临时状态。取消、失败和完成均有独立审计，不保存错误正文、链接正文或选择原因原文。

5,000 条期间身份归属证据已通过真实 SQLite 集成场景。候选和证据使用分批 `createMany`、集合去重和 60 秒有界事务，不退化为 5,000 次逐条事务；进度最终到达 100，快照和候选数量完成对账。

## 4. 聚类、候选与证据

- 确定性聚类优先使用 Jira 父任务，否则使用任务 ID；同一任务的完成状态、确认 Commit/MR/Pipeline/Release 关系归入同一成果。
- 已确认身份匹配但尚无任务关系的 Commit/MR 保留为独立待筛选候选，不武断合并、不自动选入。
- 重跑使用稳定 source key，不覆盖用户已经编辑的标题、结构化正文、选择状态或排除原因；新证据只追加，不改写历史证据，证据完整度只升级不降级。
- 每项成果保存项目、标题、Situation、Action、Result、Impact、个人贡献边界、周期、选择状态、证据状态、排序和版本。
- API 支持按选择状态、项目、人工/收集来源、证据来源、证据完整性、月份和指标过滤，并提供游标分页。
- 批量选择、排除、恢复和排序必须同时提交评审版本与逐成果版本；排除原因和其他决定原因在审计中只保存哈希。
- 一个来源证据允许支持多个成果，但列表逐证据标记 `duplicateInReview`，成果同时返回重复引用、已选无证据和已选无指标 warning。
- 人工链接使用稳定来源哈希，所以同一链接支持多个成果时可被识别；同一成果重复链接返回稳定冲突。数据库只允许一个主证据，所有成果证据不可变。

## 5. 指标映射和并发不变量

成果只有进入 `selected` 后才能映射当前评审绑定模板的指标。每条映射必须有贡献说明；空数组表示明确清空。映射不再原地覆盖：旧记录只允许从 active 迁移为 superseded，新记录递增独立版本，数据库部分唯一索引保证同一成果/指标只有一个 active 版本。

绑定新的指标模板版本会使不属于新模板的 active 映射全部失效、递增受影响成果版本并重新计算材料完整性；重复绑定同一版本是无写入重放。旧评分和旧映射历史继续保留。

所有成果编辑、选择、证据、映射、模板和评分写路径都把评审/成果版本放入最终 SQL 更新条件，而不只在事务开始时读取校验。任一并发变化会使整个事务回滚并返回版本冲突。修改成果、证据、映射、模板或评分仍会使既有季度确认失效；历史导出表不被删除。

第 22 个迁移增加指标映射 active/version/superseded 版本链、单 active 约束和单主证据约束；升级若遇历史多主证据，确定性保留最早记录后恢复不可变触发器。第 23 个迁移把成果五段结构、贡献边界、评审周期范围和证据枚举收口到数据库触发器，不能通过绕过 API 写入空壳成果。

## 6. API

| 端点                                                                 | 行为                                     |
| -------------------------------------------------------------------- | ---------------------------------------- |
| `POST /api/v1/quarterly-reviews/:id/collect`                         | 校验聚合版本并排队多来源收集             |
| `GET /api/v1/quarterly-reviews/:id/collection-snapshots`             | 返回不可变快照摘要、来源数量、警告和哈希 |
| `GET /api/v1/quarterly-reviews/:id/collection-snapshots/:snapshotId` | 返回指定快照的冻结事实                   |
| `GET /api/v1/quarterly-reviews/:id/achievements`                     | 多条件过滤、游标分页、证据/映射/warning  |
| `POST /api/v1/quarterly-reviews/:id/achievements`                    | 新增完整五段式人工成果                   |
| `PUT /api/v1/quarterly-reviews/:id/achievements`                     | 批量选择、排除、恢复和排序               |
| `PUT /api/v1/achievements/:id`                                       | 带双版本锁的成果编辑                     |
| `POST /api/v1/achievements/:id/evidence`                             | 添加不可变人工证据和贡献角度             |
| `PUT /api/v1/achievements/:id/metrics`                               | 替换 active 指标映射并保留版本历史       |
