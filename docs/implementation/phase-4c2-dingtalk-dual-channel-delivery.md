# 阶段四 C2：钉钉正式日志创建与双通道交付

## 1. 状态和边界

04C2 已实现只接受当前有效确认版本的钉钉正式日志创建、外部日志 ID 持久化、机器人提交成功短摘要、双通道独立幂等、尝试事实和页面可见的部分交付状态，状态为 `implemented`。

本增量没有把 fixture 测试描述成公司钉钉企业联调成功。当前工作区没有用户授权的测试企业、内部应用凭证、专用模板和测试群，因此不会自动调用任何真实钉钉写接口。结果查询、`unknown/needs_review` 恢复、429/5xx 有界重试、计划任务、失败提醒、降级复制/导出属于 04C3。

## 2. 正式日志协议

- 正式创建固定使用 `https://oapi.dingtalk.com/topapi/report/create`，访问令牌仍由 04C1 的新版 OAuth2 端点获取。
- 请求固定包含 `userid`、`template_id`、`contents`、`to_chat`、去重后的 `to_userids` 和 `dd_from`。
- `contents` 必须恰好包含六个字段，字段名称和顺序均唯一；字段名、类型、顺序来自确认时冻结的模板映射，正文来自同一不可变确认版本。
- 创建响应只接受已校验的 `errcode/result/request_id` 结构，明确成功后保存外部日志 ID 和供应商请求 ID。
- 当前已批准适配器不支持可靠附件上传。确认版本含附件时，服务端在创建交付意图前阻断，页面同步说明必须移除附件并重新确认或使用后续降级导出，绝不静默丢附件。
- 用户和群均先以稳定外部 ID/验证快照冻结；显式用户通过 `to_userids` 交付，群沿用经探测模板的默认会话范围，当前适配器不会把机器人 Webhook 冒充正式日志群接收能力。

## 3. 提交前事务门禁

正式提交会重新读取而非信任页面正文，并逐项验证：

1. 周报属于当前用户，状态为 `confirmed`，聚合版本未变化。
2. 请求的确认、确认版本、收件范围哈希与周报当前指针完全一致。
3. 确认仍为 `active`，模板映射仍是连接的当前版本且没有过期。
4. 连接启用、探测健康、有当前凭证，能力快照哈希与映射冻结值一致。
5. 每个接收对象验证事实仍可用、未过期，稳定 ID、类型和内容哈希没有变化。
6. 冻结版本没有当前协议不支持的附件。

任一事实变化都会要求刷新、重新探测或重新确认，不允许页面用旧正文、旧收件人或旧模板继续提交。

## 4. 双通道幂等和持久化

- 新增 `delivery_intent`：固定周报、确认、确认版本、通道、连接、请求摘要、目标摘要、幂等记录、作业、外部标识、错误分类和乐观锁版本。
- 新增 `delivery_attempt`：只保存请求摘要哈希、结果分类、请求 ID、外部 ID 和非敏感错误，不复制六字段正文、Webhook、Secret 或访问令牌。
- 唯一键 `(report_id, confirmation_id, channel, connection_id)` 保证重复点击和并发请求只返回原意图；意图与 `maxAttempts=1` 的副作用作业在同一事务创建。
- 正式日志和机器人分别拥有独立意图、尝试和聚合状态。机器人失败不会回滚或改写正式日志成功事实。
- 明确成功后的任何重放直接返回原外部 ID；网络超时先把 attempt/intent 固定为 `unknown`，随后令 `manual_review` 作业进入人工复核，禁止自动重放。
- 数据库触发器限制通道、状态、attempt 序号、意图版本递增和成功事实不可逆，避免绕过服务层破坏交付历史。

## 5. 机器人摘要安全边界

群通知只有在同一确认的正式日志意图明确成功且已有外部日志 ID 后才可创建。机器人连接必须启用、探测健康、有当前凭证且没有待提升凭证。

提交成功摘要只包含：周报周期、报告日期、成功状态、来源快照中去重后最多三个项目名、正式日志 ID，以及“在本机 Auto Work 查看详情”的说明。消息不包含六字段全文、附件内容、凭证、Webhook、Token 或不可由群成员访问的 `localhost` 链接。

## 6. 页面交互

周报工作台新增独立“钉钉双通道交付”区域：

- 正式日志按钮只在当前确认可提交且没有附件/活动或未知意图时启用，并以危险操作二次确认展示冻结版本、模板、接收范围和附件能力。
- 只有正式日志状态为 `submitted` 才能选择已测试健康且没有待提升凭证的机器人，并二次确认发送短摘要。
- 页面显示两通道状态、外部日志 ID、尝试次数、错误码、更新时间、unknown 人工复核提示和 `日志成功 + 机器人未成功` 的部分交付告警；同一连接已有失败意图时按钮保持禁用，避免把幂等重放伪装成新的重试，可改选尚无意图的健康机器人。
- 页面轮询交付事实；正在执行时同步刷新周报聚合状态。刷新或重复点击不会生成新的外部写意图。

## 7. 自动验证

04C2 新增或扩展的自动化覆盖：

- 提供方契约：固定主机/路径/query、六字段请求结构、用户去重、外部 ID/请求 ID 解析、非六字段拒绝。
- 持久化集成：完整迁移、当前确认门禁、原子 intent/job/idempotency、重复请求重放、正式成功、群摘要安全正文、部分交付、附件阻断、过期映射阻断、超时 unknown 和无第二次外部调用。
- 前端静态和测试：类型、lint、现有页面/view-model/client 回归。

企业 UAT 仍必须使用用户明确授权的专用测试应用、模板和群，消息带显眼测试标识；没有授权时只执行 stub/隔离数据库和停在二次确认前的浏览器验收。

## 8. 后续 04C3

04C3 将在本模型上增加：可查询的提交结果恢复、人工核对决议、明确失败的新 attempt、429/5xx 的 Retry-After 有界策略、机器人通知频控与去重窗口、Asia/Shanghai 计划任务和休眠补偿、失败提醒、附件/正式日志不可用时的六字段复制与导出降级。04C3 完成前，`DNG-001/002/003` 不提升为整体 `verified`。
