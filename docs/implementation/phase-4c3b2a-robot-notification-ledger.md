# 阶段四 C3b2a：机器人通知账本、安全模板与静默合并内核

## 1. 状态与边界

04C3b2a 完成独立机器人业务通知账本、四类固定安全模板、状态版本去重和内容静默窗口合并，状态为 `implemented`。提交成功摘要已接入该账本；截止/失败/风险通知的触发策略和页面设置继续由 04C3b2b 与 04C3b3 完成。

## 2. 独立通知账本

新增 `robot_notification`，不把提醒硬塞进正式日志/群摘要交付意图。每条账本记录包含：

- 周报、机器人连接、可选 delivery intent；
- 通知类型、业务对象键、状态版本、唯一去重键；
- 正文哈希、静默窗口、合并次数、计划时间；
- queued/sending/succeeded/failed/unknown/skipped/cancelled 状态；
- 非敏感请求 ID、错误摘要、发送/跳过时间和乐观锁版本。

数据库唯一键约束 delivery intent、去重键和当前 job；SQLite trigger 固定通知类型/状态枚举、静默窗口边界、非递减合并次数和终态不可回退。账本不保存完整机器人正文、六字段、Webhook、Token、Secret 或附件内容。

## 3. 去重与静默窗口

- `dedupeKey = hash(业务对象 + 通知类型 + 状态版本)`；同一状态版本重复请求直接返回原账本事实。
- 状态版本不同但业务对象、通知类型、正文哈希相同，并且仍在机器人配置的静默窗口内时，只增加原记录的 `coalescedCount`，不创建第二次外部调用。
- 已 skipped/cancelled 的旧记录不会吸收新提醒；静默窗口为 0 时不合并不同状态版本。
- 并发相同状态版本最终由数据库唯一键收敛，不能靠内存锁假装幂等。
- 连接测试继续使用原测试路径，不写业务通知账本，因此不会污染业务去重。

## 4. 四类固定安全模板

- `deadline_reminder`：周期、截止时间、草稿状态和“不会自动正式提交”提示。
- `submission_success`：日期、状态、最多三个项目和正式日志 ID。
- `submission_failure`：失败阶段、最多 240 字简化错误和本机恢复提示。
- `risk_alert`：最多三个已筛选风险摘要。

所有动态值先去除 NUL/换行/制表符、折叠空白并截断。模板函数不接受六字段全文、附件、凭证或 URL；任何通知都只提示在本机 Auto Work 查看，不发送不可访问的 localhost 链接。

## 5. 提交成功摘要接入

用户创建群摘要 intent 时，同一数据库事务内创建 job 和通知账本；任一步失败都会整体回滚。消息构造器同时用于入队哈希与真实 handler，避免去重内容和实际发送内容漂移。

handler 开始时把账本从 queued 切到 sending，完成后与 delivery attempt 同事务写入 succeeded/failed/unknown、请求 ID 和非敏感错误。原有双通道 intent/attempt 仍承担交付恢复，通知账本承担跨通知类型的去重、合并和后续调度。

## 6. 自动化证据

- 全新 SQLite 按全部迁移创建通知账本和校验 trigger。
- 提交成功摘要发送后，账本状态为 succeeded，供应商请求 ID 可核对，且序列化记录不含完整周报正文。
- 同状态版本再次预留返回 `duplicate`；下一状态版本相同内容在 30 分钟窗口内返回 `coalesced`，原记录合并数递增。
- 四类模板、换行注入清理、风险/项目数量边界和 localhost 禁令通过单元测试。
- 定向 API 类型检查以及通知/双通道交付 10 个用例通过。
