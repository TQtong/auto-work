# 阶段四 C3b3a：预约正式提交批准与执行前取消门禁

## 1. 状态与设计边界

04C3b3a 已实现“确认版本冻结未来时间 → 用户对准确时间显式批准 → 持久化队列按时执行 → 版本或确认变化时在外部调用前取消”的完整闭环，状态为 `verified`。

预约正式提交仍然是用户触发的钉钉正式日志写操作，不是后台默认自动化。生成、确认或保存 `scheduleAt` 都不会自行创建交付意图；只有用户在工作台二次确认本次准确时间后，服务端才会排队。机器人通知不具备正式提交权限，也不会作为预约失败时的替代通道。

## 2. 显式批准协议

`POST /weekly-reports/:id/submit-log` 在确认版本含未来 `scheduleAt` 时，额外要求：

- `scheduledApproval.scheduledAt` 必须与冻结版本的时间精确相同；
- `confirmationPhrase` 必须等于“我确认在计划时间自动提交钉钉正式日志”；
- 当前确认 ID、确认版本 ID、收件范围哈希、模板能力快照和周报乐观锁版本仍须通过原有门禁。

没有批准、批准时间不匹配，或当前版本没有未来时间却携带旧批准，均会在意图、作业和外部调用创建前拒绝。服务端生成批准哈希，绑定周报、确认、冻结版本、准确时间和固定短语；数据库不保存重复的正文或批准短语。

## 3. 调度事实与数据库约束

`delivery_intent` 新增计划执行时间、批准时间、批准哈希、取消时间和取消原因。迁移同时增加状态/时间索引，并用 SQLite 触发器约束：

- `scheduled_for` 必填，计划时间和批准哈希创建后不可修改；
- `cancelled` 必须记录取消时间和非空原因；
- 只有 `pending` 可以转为 `cancelled`，`succeeded/cancelled` 均为终态；
- 所有状态更新继续要求 intent 版本严格递增，外部 ID 成功事实不可覆盖。

交付意图和通用 Job 在同一事务内使用同一个计划时间。即时提交继续使用当前时间，且不伪造预约批准事实。

## 4. 编辑失效与执行前双重止损

确认后的正文、附件、收件人、模板或其他提交元数据发生变化时，周报服务会在使旧确认失效的同一事务中：

1. 找出旧确认下尚未执行的正式日志意图；
2. 把意图标记为 `cancelled`，记录中文原因和稳定错误码；
3. 把仍为 `queued` 的作业同步取消并设置 `cancelRequested`。

为覆盖“作业刚领取、编辑事务同时发生”的竞态，执行 handler 在创建 attempt 和调用钉钉前，还会原子验证：确认仍为 `active`，周报仍为 `confirmed`，当前确认和冻结版本仍与意图一致。验证失败只形成取消事实，不创建 delivery attempt，也不触发供应商调用。

## 5. 工作台可见性

- 未来时间的二次确认框明确显示准确执行时间、预约外部写操作性质和版本变化自动取消规则。
- 用户点击“批准预约正式提交”后，前端随请求发送固定批准短语和冻结时间；即时提交仍显示原有确认文案。
- 成功排队后提示计划执行时间；交付列表新增“计划/批准”列，区分预约批准与即时进入队列。
- API 返回计划、批准和取消事实，取消状态不会被页面误显示为失败、成功或可直接重试。

## 6. 自动化与迁移证据

- 未来预约不带批准时返回 `WEEKLY_REPORT_SCHEDULE_APPROVAL_REQUIRED`，且交付意图数量保持为零。
- 对准确时间显式批准后，intent 和 Job 使用同一时间，批准哈希为 64 位摘要，排队阶段不调用钉钉。
- 执行前确认失效时返回 `cancelled`，外部创建调用和 delivery attempt 数量均为零。
- 通过真实周报编辑链验证：确认失效、预约 intent 取消和 queued Job 取消在同一业务事务内完成。
- 定向 API 集成测试 2 个文件/20 个用例通过，Web 交付视图模型 1 个文件/5 个用例通过。
- Prisma schema 校验通过；第 18 个迁移已在本地数据库实际部署，`prisma migrate status` 显示数据库为最新状态。
- 全量 `pnpm verify` 通过：Contracts 1 个文件/2 个用例、Domain 7 个文件/28 个用例、API 36 个文件/187 个用例、Web 6 个文件/17 个用例全部通过；格式、lint、类型检查和生产构建同时通过。

本增量没有使用企业钉钉凭证，也没有把 fixture 结果表述为企业联调成功。预约排队和取消路径的自动化测试使用替身客户端，并明确断言取消场景没有外部调用。
