# 阶段四 A3a：周报编辑、恢复与确认内核

## 1. 本增量边界

本增量完成 04A3 的后端状态机：六字段和提交元数据编辑、乐观锁、不可变父子版本、历史恢复、附件实体、钉钉模板映射版本、收件人验证快照、warning 知悉、幂等确认以及确认后编辑失效。状态为 `implemented`。周报工作台、字段比较/撤销重做/自动保存交互和真实浏览器验收仍在 04A3b 完成，因此 `AC-WRP-03/04` 尚不能标为 `verified`。

## 2. 不可变版本与乐观锁

- `PUT /api/v1/weekly-reports/:id` 必须同时提交当前 `baseVersionId`、聚合 `reportVersion`、变更原因和 `Idempotency-Key`；正文、附件、收件人、模板映射或计划时间任一变化都会创建新的 `manual` 版本，不原地覆盖。
- 新版本同时冻结六字段纯文本、结构化块、warning、附件事实、收件人事实、模板映射版本、计划时间、来源快照、父版本、变更摘要与覆盖全部内容的哈希。未改变字段保留原结构块；人工改写字段生成稳定块并继承明确来源链接。
- `POST /api/v1/weekly-reports/:id/versions/:versionId/restore` 不移动旧指针，也不覆盖当前版本，而是复制目标历史事实并创建新的 `restore` 版本。由此撤销/重做可以复用同一恢复语义，历史始终可回放。
- 所有编辑与恢复使用条件更新抢占聚合版本；过期页面统一返回 409 `VERSION_CONFLICT`。成功结果和幂等记录在同一事务提交，避免正文已写入但重试重复创建版本。

## 3. 正式附件

- `POST /api/v1/weekly-reports/:id/attachments` 只接受单文件 multipart，最大 8 MiB，支持 PDF、DOCX、XLSX、PNG、JPEG、TXT；扩展名、MIME 和文件魔数必须一致。
- 原始文件名仅作显示；服务端使用随机 ID 生成存储名，并保存大小与 SHA-256。文件写入失败不创建数据库事实，数据库创建失败会删除刚写入文件。
- 版本只引用属于当前周报且状态为 `available` 的附件事实。确认时重新读盘并核对文件存在性、大小和 SHA-256，防止磁盘文件被替换。
- 被当前版本引用的附件不能删除；先保存一个移除引用的新版本后才能将附件标为 `deleted`。历史元数据和文件保留用于审计，不伪装成物理清除。

## 4. 钉钉模板映射与收件人事实

- `POST /api/v1/integrations/:id/dingtalk/template-mappings` 仅接受已启用、状态健康的 `dingtalk_log` 连接，并要求提交的能力快照哈希与连接最近真实探测结果完全一致。
- 模板必须完整映射 `reportDate/recentGoals/weeklyWork/nextWeekPlans/problems/other` 六字段，内部字段、外部字段 ID 和顺序均唯一；保存后形成不可变版本，聚合只更新当前版本指针。
- `GET /api/v1/integrations/:id/dingtalk/template-mappings` 返回当前指针与全部历史；`GET /api/v1/integrations/:id/dingtalk/recipients` 返回外部适配器写入的收件人验证缓存及过期状态。
- 收件人验证快照为只追加事实，冻结连接、主体类型、外部稳定 ID、显示名、能力快照、观测时间、失效时间与内容哈希。编辑只能引用已存在且可用的快照，不接受前端自报的任意姓名或 ID。

## 5. 确认门禁与失效

`POST /api/v1/weekly-reports/:id/confirm` 必须提供当前版本、聚合版本、模板映射版本、全部 warning 知悉 ID 和 `Idempotency-Key`。服务端在单一事务中验证：

1. 当前版本和聚合版本没有并发变化；
2. 六字段全部非空，问题栏明确填写，报告日期位于周期内，计划时间未过期；
3. 模板映射仍是当前版本、未过期、连接健康、能力快照未变化，正文长度满足每个外部字段限制；
4. 阻断 warning 为零，所有非阻断 warning 的稳定哈希 ID 已逐项知悉；
5. 附件数据库事实和磁盘内容一致；
6. 至少一个收件人属于模板连接，验证快照可用、未过期且内容哈希未变化。

确认记录锁定版本 ID、正文哈希、模板映射版本、warning 知悉明细、收件人范围哈希和附件哈希，并把周报切换为 `confirmed`。相同事实重复确认返回原确认；确认后的任何正文或提交元数据变化都会生成新版本，把旧确认追加为 `invalidated` 并保留原因、确认人和确认时间，周报回到 `editing`。

## 6. 数据库约束与审计

- 新增模板映射聚合/版本、收件人验证快照、周报附件和周报确认四组实体。
- 模板映射版本、收件人快照继续使用 UPDATE 阻断触发器；附件证据字段不可变，只允许生命周期删除；确认锁定字段不可变，只允许从 active 追加失效状态与原因。
- 编辑、恢复、确认、模板映射保存、附件上传/移除均记录中文语义审计；拒绝路径由控制器记录请求哈希与错误码。
