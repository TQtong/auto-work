# 阶段四 A1：六字段周报确定性规则内核

## 1. 当前增量状态

本增量建立“规则先行、AI 后置”的周报纯领域内核。它只消费调用方已经白名单化的任务、证据和人工输入，不读取源码、diff、附件、环境变量或外部系统；同一来源快照可以稳定复算出相同块 ID、来源引用和内容哈希。

04A1 已达到 `implemented`。周报快照/不可变版本/编辑确认状态机、AI 三协议、钉钉正式日志和机器人交付尚未完成，因此阶段四不能视为 `verified`。

## 2. 已实现的完整规则

- 严格保存并校验 `periodStart`、`periodEnd`、`reportDate` 和 `Asia/Shanghai`，以上海零点作为半开时间边界，不会遗漏周一凌晨或混入下周数据。
- 近期目标只从当前用户可见且未完成的 Sprint、blocked、未来 14 天开始/到期任务和人工目标产生；按项目/父任务分组，每组最多 3 条，人工置顶优先。
- 本周工作只使用本周状态变化/观测任务及已确认关系，按任务聚合 Commit、MR、Pipeline、Release 等证据，只输出数量和类别，不逐条复制 Commit message。
- 实际工时与预估工时分别保存；空值、负值和 0 均保持 `null`，不会把 Excel 空工时误写为 0 小时。
- 下周计划排除 done/cancelled；对当前进行中、Sprint、下周开始/到期及逾期未完成任务生成“继续推进/计划开展/继续收尾”语义，不把顺延任务伪装成新计划。
- 问题字段覆盖 blocked、逾期未完成和已确认失败 Pipeline；不从普通延期猜责任方。没有问题和人工输入时精确生成“暂无”。
- 人工输入按五段正文分别保留，使用稳定人工来源 ID，不因文字相似而删除事实。
- 任务和证据 stale/unavailable、待确认证据、未配置企业工作日历均形成结构化 warning；它们不被静默丢弃，也不会被规则擅自提升为 blocking。
- 每个段落保留 task/evidence/manual 来源引用，输出包含完整来源 ID 清单、规则版本和稳定内容哈希，为后续不可变快照、字段级追溯和 AI 引用校验提供事实基础。

## 3. 自动化证据

`weekly-report-rules.spec.ts` 包含 7 组黄金样例：

1. 目标、本周工作、下周计划、blocked/逾期问题和空工时；
2. 多 Commit 聚合、禁止复制 message、失败 Pipeline 不得表述为已发布；
3. 无问题精确“暂无”、人工置顶目标和其他补充；
4. 企业日历回退、任务/证据 stale/unavailable、未确认证据警告；
5. 输入数组乱序时块 ID、字段顺序和内容哈希稳定；
6. 非法周期、越界填写日期、非上海时区、重复来源和空人工输入全部阻断；
7. Asia/Shanghai 周一零点与下周边界。

当前 domain 共 7 个测试文件、28 个测试全部通过，同时通过 Prettier、ESLint 和 TypeScript 类型检查。

全仓 `pnpm verify` 通过：contracts 2、domain 28、API 100、Web 5，合计 135 个测试；格式、Lint、类型检查和 API/Web 生产构建全部成功。
