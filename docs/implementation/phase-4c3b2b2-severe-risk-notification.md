# 阶段四 C3b2b2：严重风险规则配置与受控通知

## 1. 状态与设计边界

04C3b2b2 实现“机器人显式配置严重规则 → 周报工作台只列出当前版本匹配 warning → 用户最多选择三项 → 服务端重验并生成固定短摘要 → 通知账本发送”的完整闭环，状态为 `verified`。

风险提醒是可选群通知，不是正式日志、审批或自动升级机制。默认规则清单为空；保存配置不会发消息，每次发送仍需用户在周报工作台明确选择机器人、warning 并二次确认。

## 2. 前后端共享规则目录

`@auto-work/contracts` 提供唯一的周报 warning 规则目录，包含规则代码、中文名称和解释。目前覆盖：

- `SOURCE_UNAVAILABLE`：来源不可用；
- `SOURCE_STALE`：来源数据过期；
- `UNCONFIRMED_EVIDENCE`：证据尚未确认；
- `WORKDAY_CALENDAR_FALLBACK`：工作日历降级；
- `AI_GENERATED_CONTENT`：包含 AI 建议。

机器人非秘密配置新增 `severeRiskCodes`。集成服务使用严格枚举、去重和最大数量校验，客户端自造规则代码会在保存前被拒绝。既有机器人没有该字段时按空清单处理，因此不会因为升级而意外启用风险外发。

设置页的新建表单和“严重风险规则”独立编辑弹窗都使用共享目录。编辑只更新 `config` 和乐观锁版本，不读取、回显或替换保险箱凭证；同时允许配置 0–1440 分钟的相同正文静默窗口。

## 3. 风险通知 API 强校验

`POST /weekly-reports/:id/notifications/risk` 必须携带幂等键以及：

- 用户明确选择的健康机器人 ID；
- 当前不可变周报版本 ID 与周报聚合乐观锁版本；
- 1–3 个不重复、格式有效的 warning ID。

服务端重新读取当前用户周报、当前版本和机器人配置，并逐项验证：

1. 请求版本仍是报告的 `currentVersionId`，聚合版本未变化；
2. warning ID 由当前版本原始 warning 事实规范哈希得到，不能由客户端伪造；
3. warning 的规则代码存在于目标机器人 `severeRiskCodes`；
4. 机器人仍启用、测试健康、没有待启用凭证且当前凭证可用。

任一条件变化都会在通知账本和外部调用创建前拒绝，并要求刷新或重新配置。

## 4. 最小外发与冻结事实

工作台可以在本机显示 warning 原文供用户判断，但机器人正文不复制原文。任务标题、客户名称、来源摘要可能出现在 warning message 中，因此服务端只把共享目录中的规则中文名、规则代码和本次选择数量写入冻结事实，例如“来源不可用（SOURCE_UNAVAILABLE，选中 1 项）”。

完整六字段、warning 原文、来源引用、附件、客户信息、Token、Webhook、Secret 和 localhost 链接均没有进入发送事实或机器人正文的路径。后台作业继续使用 C3b2a 的不可变 `message_facts_json`、正文哈希复算和严格类型校验。

## 5. 去重、静默合并与作业证据

- 业务对象键包含周报 ID 与排序后的 warning ID 集合哈希；状态版本采用当前不可变版本号。
- 同一选择集合、同一版本重复提交返回既有通知和 job，不产生第二次供应商调用。
- 新版本仍得到新的状态版本；若冻结正文完全相同且仍在机器人静默窗口，则合并到既有通知并递增 `coalescedCount`。
- 新通知使用 `weekly-report.notification` 单次作业、机器人 429/5xx 有界重试、调用次数/退避序列证据和 unknown 人工复核语义。
- 审计只记录报告、机器人、版本、warning ID/代码、正文哈希与处置结果，不记录 warning 原文或凭证。

## 6. 工作台交互

- 只有已测试健康、无待启用凭证的机器人可供选择。
- 页面从当前版本 warning 与所选机器人规则配置的交集生成候选；无候选时发送按钮禁用。
- 弹窗显示安全边界，最多允许选择三项；达到三项后其余候选不可再选。
- 提交后展示 created、duplicate 或 coalesced 的明确结果，通知状态、调用次数和静默合并数继续出现在统一通知账本。
- 页面筛选只是减少误操作；服务端强校验才是授权边界。

## 7. 自动化证据

- 集成配置缺省严重规则为空，自造代码被拒绝且不会落库。
- 当前版本中两项已配置 warning 可生成风险通知；未配置 warning 不进入冻结事实。
- 实际机器人正文只含规则类别/代码/数量，不含本机可见 warning 原文和完整周报正文。
- 同版本相同选择、不同输入顺序命中同一去重事实。
- 新状态版本相同正文命中静默合并，供应商调用仍只有一次。
- 伪造 warning ID 和当前版本存在但未配置的规则均被拒绝，且不创建通知账本。
- Web 视图模型只保留共享目录内、机器人已配置、当前版本真实存在且有本机说明的 warning。
- 真实浏览器验收确认：无健康机器人时风险按钮禁用；临时健康机器人配置匹配规则后按钮启用；风险弹窗未选择时确认禁用、选择后启用；规则编辑弹窗正确回显 `WORKDAY_CALENDAR_FALLBACK` 和 30 分钟静默窗口。验收没有点击发送，临时机器人无通知/交付引用并已清理。
- 全量 `pnpm verify` 通过：Contracts 1 个文件/2 个用例、Domain 7 个文件/28 个用例、API 36 个文件/186 个用例、Web 6 个文件/17 个用例全部通过；仓库格式、lint、类型检查和生产构建同时通过。

## 8. 后续增量

04C3b3 将实现 Asia/Shanghai 提醒计划、休眠恢复宽限补发/超时 `skipped`，以及正式日志能力不可用时的复制与导出降级。风险通知不会替代这些调度或正式交付能力。
