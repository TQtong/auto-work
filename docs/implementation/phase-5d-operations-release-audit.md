# 阶段五 D：运维恢复、发布工程与终审

## 1. 当前结论

05D1 至 05D3 的诊断、容量、留存、备份恢复、发布门禁、Windows 安装升级回滚和运行手册已经实现并获得自动化、真实浏览器和候选发布包证据。05D4 的全量需求/验收标准终审仍在进行，因此总增量保持 `implemented`，不会用局部发布门禁替代全仓需求完成证明。

## 2. 脱敏诊断与容量

- 运维页展示应用/Node、loopback 监听、schema、SQLite WAL/page/quick check、受控目录分类、作业计数、外部集成健康、最近备份和不可变审计数量；
- 诊断包在生成前列明包含项和排除项，必须显式勾选；输出使用临时文件和原子改名，记录 SHA-256；
- 事实自检阻断 Authorization、Bearer、credential、access token、Webhook 和 payload 等秘密类别；排除项可以描述这些类别，但不会被当作实际泄漏；
- 磁盘增长门禁使用 `max(1 GiB, 卷容量 5%)`，阻断 Excel 预览、季度导出、备份和诊断包新增，已有数据仍可读；
- `diagnostics.service.spec.ts` 覆盖事实脱敏、包生成和低磁盘阻断。

## 3. 留存预览与受控执行

- 策略分别配置结构化事件、终态作业和诊断包保留天数，并实施 7/30/7 天最低值；
- 预览返回逐类候选、永久保留边界和完整哈希；执行必须携带相同哈希；
- 候选、永久保留计数或范围发生变化时返回 409，要求重新预览；
- 自动清理只涉及旧 AppEventLog、过期幂等、旧终态作业和旧诊断包；不可变审计、业务事实、导出制品、已校验备份和凭证永不自动清理；
- `retention.integration.spec.ts` 在全部迁移的真实 SQLite 上验证成功清理和预览漂移拒绝。

## 4. 一致备份与启动前恢复

- 备份使用 SQLite `VACUUM INTO`，记录文件名、大小、SHA-256 和当前 schema；
- 隔离校验重新计算哈希，在独立 Prisma 连接执行 `quick_check`、`foreign_key_check` 并读取备份 schema；
- 恢复预检只允许 `verified`、哈希存在且与当前 schema 兼容的制品；页面要求精确输入 `恢复 <fileName>` 并确认重启；
- 恢复准备作业再次核对哈希/schema、checkpoint WAL、创建当前库安全备份，再写入待重启清单；
- 下次启动在 Prisma 建连前复制并复核源文件，原子移动当前库为紧急备份，清除精确旧 WAL/SHM，再切换恢复库；失败时恢复原库；
- 重启前可以取消清单，已生成备份继续保留；
- `backup-recovery.integration.spec.ts` 与 `pending-restore.spec.ts` 覆盖预检、强确认、准备、篡改拒绝、成功切换和失败回滚。

## 5. 发布与供应链

- 固定 `@cyclonedx/cdxgen 12.6.0`，生成 CycloneDX 1.6；工具退出成功后仍再次解析 UTF-8 JSON、根版本、四个工作区组件和依赖图；
- Git 跟踪文件秘密扫描覆盖私钥和主流平台高置信 Token 格式，并拒绝凭证文件；
- 生产依赖审计以 high 为失败阈值；React Router 从 7.10.1 升至 7.18.1，消除 6 个高危公告；
- GitHub Actions 使用 Windows runner，所有第三方 action 固定到完整 commit SHA；
- `release:package` 自身强制重新生产构建，避免陈旧 `dist`；ZIP 内含版本、Git commit、schema、生产构建、迁移、SBOM、逐文件 SHA-256、运维脚本和手册，ZIP 外另有 SHA-256；
- `pnpm release:gate` 使用隔离数据库，依次执行全仓 verify、schema 校验、26 迁移部署/状态、秘密/依赖扫描、SBOM 和候选包生成。

## 6. Windows 安装、升级与回滚

- 首次安装校验 500 个发布文件，拒绝磁盘根和已有安装，使用 `--prod --frozen-lockfile` 安装 326 个生产包，生成 Prisma Client，部署并核对 26 个迁移后才更新版本指针；
- 运行环境固定 Node `>=22.14 <23` 和 pnpm 10.14；每次 pnpm 运维命令显式加载版本 `.env` 并在结束后恢复进程环境，数据库只落共享 `data`；
- 启停使用带启动时间的 PID JSON，防止 PID 复用误杀；启动必须通过 loopback 健康检查；
- 升级先通过受 CSRF 保护的本机 API 创建并隔离校验备份，备份必须具备 verified、SHA-256 和合法 schema；迁移成功后才切换版本，并记录升级历史；
- 同 schema 回滚只切应用指针；不兼容 schema 必须提供 backups 目录内文件、精确 SHA-256、目标 schema 和强确认文本，通过启动前原子恢复回到升级前库；
- 安装、升级、回滚、故障处理、已知限制和人工发布签字项均已形成可执行中文文档。
