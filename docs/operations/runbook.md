# 运维故障处理手册

## 1. 通用原则

1. 先停止进一步写入，记录时间、操作 ID、连接和作业状态；
2. 在运维页下载脱敏诊断包；诊断包不会包含凭证、Webhook、原始外部响应、源码/diff 或业务正文；
3. 不重复执行状态为 `unknown` 的外部写操作；
4. 不直接编辑 SQLite，不覆盖活动 db/wal/shm；
5. 恢复后核对审计、作业账本和外部系统事实，再关闭事件。

## 2. 端口占用

症状：启动时报 `EADDRINUSE`，健康检查超时。

```powershell
Get-NetTCPConnection -LocalPort 3760 -State Listen | Select-Object LocalAddress,LocalPort,OwningProcess
Get-CimInstance Win32_Process -Filter "ProcessId=<PID>" | Select-Object ProcessId,ExecutablePath,CommandLine
```

只有确认 PID 属于过期 Auto Work 后才能停止。未知进程不得强杀；改用 1024–65535 的空闲端口重新安装/修改该版本 `.env`，同时保持 `AUTO_WORK_HOST=127.0.0.1`。不得绑定 `0.0.0.0`。

## 3. 数据库 locked

症状：写操作返回数据库忙、作业重试。

- 检查是否有第二个 Auto Work、数据库浏览器、杀毒扫描或备份软件持有文件；
- 关闭数据库浏览器，确保只运行一个应用实例；
- 等待短事务结束并观察作业重试，不连续点击提交；
- 持续锁定时停止应用，保留 db/wal/shm 原状，收集诊断后重启；
- 不使用文件复制或删除 WAL 解决 locked。

## 4. 数据库 corrupt

症状：诊断 `quick_check` 非 `ok`、Prisma 读取失败或启动异常。

1. 立即停止应用并复制整个数据目录到只读事件目录；
2. 不在损坏库上运行迁移、VACUUM 或人工 SQL；
3. 在运维页历史记录中选择最近的 `verified` 备份，核对 SHA-256 和 schema；
4. 使用恢复预检、精确确认文本和重启确认准备恢复；
5. 重启后核对 `integrity_check`、外键、schema 和关键业务数量；
6. 保留 `pre-restore-emergency-*`，直到业务验收完成。

没有已验证备份时停止处理并交由数据恢复人员，不能把“能打开”当作完整性通过。

## 5. 磁盘不足

症状：运维页低容量告警，导出、备份、诊断包返回 `DISK_SPACE_LOW`。

- 阈值为卷容量 5% 与 1 GiB 中较大者；已有数据仍可读取；
- 先在留存预览中确认候选和保留边界，再输入确认执行；
- 可清理终态作业、过期幂等记录、过期事件日志和诊断包；
- 审计、业务事实、导出、已验证备份和凭证不会自动删除；
- 不绕过门禁继续生成大文件。释放空间后刷新诊断，再重试原作业。

## 6. Git 凭证弹窗或超时

- 受限 Git Worker 设置 `GIT_TERMINAL_PROMPT=0`；出现弹窗说明调用不在受控路径或系统凭证助手异常；
- 取消弹窗，记录仓库和动作，不能在弹窗输入密码后继续批量；
- 检查远端 URL、Windows Credential Manager 和企业代理；
- 原批次逐仓保留结果，失败仓库重新预检并再次批准，成功仓库不回滚；
- Index/HEAD/远端事实变化会使旧预检失效，禁止复用批准。

## 7. Jira 字段失效

症状：能力探测报告字段缺失/类型变化，映射版本过期，同步降级。

1. 暂停提交映射变更；查看缓存 `asOf` 和 stale 标识；
2. 用只读测试账号重新探测字段白名单；
3. 重新创建并确认不可变映射版本；
4. 先在少量任务同步验证，再恢复全量；
5. Excel 补充不得覆盖 Jira 非空字段，Jira 后续出现值时 Excel 来源失效。

权限不足或字段仍不可用时保持降级，不能把连接标为健康。

## 8. GitLab 429

- 尊重 `Retry-After`，不要手工并发刷新；
- 页面继续显示带 `asOf` 的缓存和 stale 状态；
- 核对 Token 权限、代理和实例限流策略；
- 等待窗口后只重试失败页/项目，禁止清空已有成功缓存；
- 多次 429 时降低同步频率并联系实例管理员。

## 9. 钉钉正式日志 unknown / 重复风险

网络超时或断连后状态为 `unknown`，系统会阻止第二次外部调用。

1. 不点击普通重试；
2. 使用窄时间窗和冻结六字段精确查询外部事实；
3. 唯一命中则记录外部 ID 并裁决“已找到”；
4. 明确零命中且人工核对后，输入强确认短语裁决“确认未创建”；
5. 多命中或事实不清时继续保持 unknown 并升级人工处理。

机器人通知是独立账本；正式日志成功、机器人失败时只能补发机器人，不能重提正式日志。

## 10. 机器人签名失败

- 核对连接健康、时间同步、secret 引用和 Webhook 掩码，不在日志粘贴完整 URL；
- 签名错误为确定性失败，修正连接并重新探测后才能重试；
- 网络超时进入 unknown 时先查群消息事实；
- 严重风险和提醒规则默认关闭，不能为了验证而向正式群自动发送。

## 11. AI 数据拦截

症状：请求被策略阻断并列出敏感类别。

- 这是安全门禁，不应关闭；
- 移除源码、diff、附件、Authorization、Token、私钥、连接串、手机号等敏感内容；
- 检查脱敏预览和移除类别，得到允许后再显式生成；
- AI 不可用或持续阻断时使用规则生成与人工编辑，不能让模型填写最终分、选成果或调用工具；
- 不把原始被拦截文本写入故障单或诊断包。

## 12. 备份失败

- 先检查磁盘门禁、数据目录权限、数据库 locked 和作业错误码；
- 失败的 `.tmp` 不得改名冒充备份；
- 只有 SHA-256、quick check、外键和 schema 全部通过才标记 `verified`；
- 修复原因后创建新备份，不覆盖旧记录；
- 连续失败时暂停升级和高风险写操作。

## 13. 升级迁移失败

1. 保持应用停止，保存终端输出、发布清单、升级历史和已验证备份哈希；
2. 确认 `current.version` 仍指向旧版本，不直接启动；
3. 在新版本目录运行 `pnpm db:status` 判断迁移是否部分应用；
4. 若数据库 schema 仍与旧版本相同，可在评审后启动旧版本；
5. 若 schema 已变化，必须用升级前备份走不兼容 schema 回滚；
6. 恢复后核对完整性、外键、schema、审计和核心数量；
7. 修复迁移必须新增前向迁移，禁止修改已发布迁移历史。

## 14. 外部平台整体不可用

健康检查中的 readiness 不要求外部平台健康。本机任务、Excel、规则周报、人工成果和本地导出应继续可用。所有外部状态必须显示真实降级、最后成功时间和建议动作；禁止伪造成功或悄悄丢弃待处理事实。
