# 已知限制与使用边界

## 已实现但受部署环境约束

- 产品是 Windows 单用户本机工作台，只监听 loopback，不支持远程访问、多用户并发、服务端集群或移动端。
- 凭证使用当前 Windows 用户范围 DPAPI；更换 Windows 用户、重装系统或复制数据库不会自动迁移秘密，必须重新配置。
- Jira、GitLab、钉钉和 AI 通过能力探测适配版本差异。没有企业测试账号时只能验证协议 fixture 和明确降级，不能宣称目标企业实例联调通过。
- GitLab/Jira 首版读取元数据；Jira 不做通用字段写回。Git 写操作仅限设计中的固定动作，不提供任意 shell。
- 钉钉超时无法从网络异常本身判断外部是否创建，必须通过查询或人工裁决收敛，系统故意阻止盲目重试。
- AI 只生成建议，不能访问源码、diff、附件或工具，也不能选成果、填写最终分或替代用户确认。

## 发布与运维边界

- 发布包提供 SHA-256 和 CycloneDX SBOM，尚未提供 Authenticode 代码签名或可信时间戳。哈希证明完整性，不证明发布者身份。
- 安装方式是可审计 PowerShell 用户级安装脚本，不是 MSI/MSIX，也不会自动创建开机启动、Windows 服务、桌面快捷方式或自动更新任务。
- 升级要求当前应用可访问，以创建并验证一致性备份。数据库已经损坏时应先恢复，不能用升级绕过。
- 数据库 schema 不兼容时，回滚会恢复升级前备份，因此升级后的本地变更会丢失。
- 留存执行只清理明确列出的可再生/终态数据；审计、业务事实、导出、已验证备份和凭证需人工制定更长期归档策略。
- 首版诊断仅在本机展示和下载，不向外部监控平台发送遥测。

## 正式投用前仍需企业确认

- 用获批、可丢弃的 14 仓集合复跑仓库发现和批量 Git UAT；
- 用公司实际 Jira/GitLab 版本、代理和权限完成只读联调；
- 用测试钉钉应用/群完成成功、失败、429/超时 unknown 和防重复演练；
- 确认真实 Excel 模板、钉钉模板和季度 Excel/Word 格式；
- 在目标机器完成安装、休眠恢复、磁盘不足、备份恢复、升级和回滚演练；
- 由安全负责人评审当前 3 个中危生产依赖公告及其实际可达性。

缺少上述证据不影响本机功能在离线/降级模式下保持真实，但候选版本不能被描述为已通过企业生产发布批准。
