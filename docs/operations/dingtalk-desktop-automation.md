# 钉钉桌面正式日志（无接口权限）

## 适用场景

当用户是公司普通员工，无法申请应用、OpenAPI、AppKey、CorpID、UserID 或日志权限，但能够在 Windows 钉钉客户端中手工进入公司工作台并提交周报时，使用本适配器。

管理后台只显示用户创建或管理的组织，不作为公司员工身份的判断依据。本适配器不访问管理后台，也不读取或保存钉钉账号、密码、Cookie、Token。

## 工作流程

1. 到达已批准的周报提交时间后，作业先锁定当前确认版本和唯一交付意图。
2. 桌面执行器启动或激活当前用户的钉钉客户端。
3. 校验公司名称，依次进入“工作台 → 日志 → 指定周报模板”。
4. 使用 Windows 内置中英文 OCR 识别钉钉内嵌页面中的六个字段，并填写确认版本中的六项正文。
5. 校验指定接收群在表单中可见。
6. 保存提交前截图，点击提交，等待明确的成功提示并保存提交后截图。
7. 只有识别到成功提示且取得本地自动化回执时，交付账本才记录成功。

若点击提交后没有识别到明确结果，作业进入 `unknown`，禁止自动重放。由于没有公司日志读取权限，用户必须在钉钉客户端中核对后执行“人工裁决”。

## 本机模式

Windows 发布包或源码 API 直接运行在当前登录用户下时，不需要额外桥接进程。进入“设置与集成”，创建“钉钉桌面正式日志（无需接口权限）”，填写：

- 钉钉客户端左侧组织切换按钮显示的组织名称（不是个人管理后台组织名，也不是日志页水印公司名）；
- 周报模板名称；
- 默认接收群；
- 可选的钉钉客户端路径；
- 单步等待上限。

保持钉钉登录并打开电脑，点击“测试”。测试会定位公司、模板、六字段和默认接收群，但不会填写内容或点击提交。连接健康后，在周报页保存六字段映射和接收群事实，之后可使用现有的确认、预约提交和幂等交付流程。

## Docker 模式

容器不能访问宿主机交互桌面。`compose.yaml` 已将 `./data/desktop-bridge` 挂载为一次性请求/响应目录。推荐在当前 Windows 用户下安装登录任务：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Install-DingTalkDesktopBridgeTask.ps1 `
  -BridgeRoot .\data\desktop-bridge
```

任务安装后立即启动，并在当前用户每次登录时自动运行；它使用交互用户的有限权限，不注册 Windows 服务。卸载命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Install-DingTalkDesktopBridgeTask.ps1 -Uninstall
```

若只想临时运行，可直接执行 `Start-DingTalkDesktopBridge.ps1`。桥接进程必须运行在与钉钉相同的已登录、未锁屏 Windows 会话中。它只处理本地目录中的请求，未监听网络端口。请求完成后 API 和桥接都会清理一次性正文文件。

桥接进程每秒在共享目录写入 `heartbeat.json`。Docker 模式在创建正式提交任务前必须读取到 15 秒内的有效心跳；桥接未运行、心跳过期或共享目录挂载异常时，接口会立即拒绝排队并提示恢复桥接，不再等待完整桌面自动化超时。每个请求同时携带绝对过期时间；旧版本请求缺少该字段时最多保留 10 分钟，超期请求会被桥接拒绝，避免重启后误提交旧周报。

## 安全与防重复

- 公司、模板、六字段和接收群任一项无法确认时停止，不点击提交。
- 不保存屏幕绝对坐标；外层客户端通过 UI Automation 校验，内嵌日志页通过 Windows OCR 文本和窗口相对位置定位。
- 长表单会逐字段滚动到可见区域后填写。
- 提交前后截图保存在 `data/dingtalk-desktop-evidence`，不进入普通诊断日志。
- 数据库中的“报告 + 确认版本 + 连接”唯一交付意图阻止重复创建。
- 作业中断、超时或成功提示不明确时进入人工复核，绝不自动重试。
- 预约提交仍要求用户对准确时间输入原有确认短语，桌面适配器不会绕过业务批准。

## 运行条件与限制

- 仅支持 Windows 交互桌面；锁屏、注销、远程会话断开或钉钉登录失效时无法执行。
- 钉钉客户端更新导致控件名称或可访问性树变化后，需要重新测试连接。
- 日期控件支持当天和历史日期；点击后必须再次 OCR 识别到目标日期，否则在提交前停止。
- 当前只自动填写六字段文本，不自动上传附件。
- 自动填写会临时使用 Windows 剪贴板；无论成功或失败，执行结束后都会清空剪贴板，避免周报正文残留。
- “测试连接”为校验模板必须打开一次填写页，不会填写或提交内容，但钉钉可能自动留下一个空白周报草稿，可在钉钉草稿列表中手动删除。
- 本地 `desktop:<runId>` 是自动化审计回执，不是钉钉 OpenAPI 日志 ID。
- 无接口权限时不能自动查询“我发出的日志”；未知结果只能人工核对。

## 发布前 UAT

使用可丢弃的真实周报完成一次人工见证测试：

1. 测试连接能识别正确公司、模板和六字段；
2. 故意配置错误公司/接收群，确认执行器停止且没有点击提交；
3. 提交一份测试周报，核对六字段、接收群、提交时间及钉钉正式日志记录；
4. 在点击提交后人为关闭窗口，确认系统进入 `unknown` 且没有自动重放；
5. 核对提交前后截图、交付意图、尝试记录和审计事件一致。
