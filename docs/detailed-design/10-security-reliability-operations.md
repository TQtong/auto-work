# 10 安全、可靠性与运维设计

## 1. 保护目标

1. 防止 Git/Jira/钉钉/AI 凭证泄漏。
2. 防止本机 Web 或 Git Worker 被利用执行任意命令/越界访问文件。
3. 防止未经批准的 Git 写、正式周报提交和数据外发。
4. 防止重复提交、同步漏数、崩溃后状态误判和历史不可追溯。
5. 在外部服务失败时保持本地数据可用和恢复路径清晰。

## 2. 威胁模型

| 威胁 | 典型路径 | 控制 |
|---|---|---|
| 本机恶意网页调用 localhost | CSRF/DNS rebinding/WebSocket | loopback、Host allowlist、Origin/CSRF、SameSite、拒绝任意 CORS |
| 命令注入 | 分支名、文件名、remote、raw args | 固定动作、参数数组、`--`、Git 语义校验、无 Shell |
| 路径逃逸 | 仓库路径、junction、上传文件名 | 内部 ID、realpath、根目录边界、拒绝重解析逃逸 |
| 密钥泄漏 | DB、日志、错误、截图、URL | DPAPI/凭据管理器、引用、统一脱敏、禁止 query secret |
| SSRF | AI base URL、集成 URL、重定向 | host/scheme policy、解析后 IP 校验、禁止 link-local/metadata、重定向复核 |
| 数据外发 | AI prompt、机器人正文 | 字段白名单、秘密扫描、用途授权、发送前数据类别预览 |
| 重放/重复副作用 | 双击、超时重试、作业恢复 | 幂等键、意图表、外部结果查询、唯一约束 |
| 缓存误导 | 外部不可用仍展示旧状态 | asOf/stale、来源健康、确认告警 |
| 供应链/依赖漏洞 | npm 包、导入解析器 | lockfile、SBOM、漏洞扫描、最小依赖、升级评审（实施阶段） |

## 3. 本机 Web 防护

- 默认只绑定 `127.0.0.1` 和可选 `::1`，Host 仅允许明确的 localhost/loopback host:port。
- 不启用通配 CORS；API 只接受自身静态站点 Origin。
- 生成本机会话秘密和 CSRF token；Cookie HttpOnly、SameSite=Strict，生产本机 HTTP 下按能力设置 Secure/替代双提交策略。
- 改变状态的方法拒绝简单跨站内容类型；文件上传同样校验 CSRF。
- CSP 默认 `default-src 'self'`，限制 connect/img/style/script；外部链接使用安全打开属性。
- 前端不将秘密写入 localStorage/sessionStorage、URL、错误追踪或剪贴板历史。
- 端口被占用时拒绝自动改为公网监听，给出明确诊断。

## 4. 密钥生命周期

### 4.1 存储

首选 Windows Credential Manager；若使用 DPAPI，采用 CurrentUser scope、每条随机数据密钥/完整性保护，并把密文放受限本机文件或保险箱，数据库仅存 opaque ref。不能用代码内固定密钥或可逆“加密字段”自欺。

### 4.2 使用

- 只有对应适配器在请求构造的最短时间读取秘密。
- 不把秘密放环境变量传给 Git/子进程；Git 使用现有凭证链。
- HTTP 客户端的调试日志默认不记录 Authorization、query、body。
- 故障对象保存错误分类和供应商 request ID（确认非敏感），不保存完整请求。

### 4.3 替换、禁用、撤销

替换新秘密先测试，通过后原子切换引用，再删除旧保险箱条目。撤销本地配置删除秘密并使连接 invalid；如果用户要在外部平台真正吊销 Token，系统提供说明/链接但不能声称已外部吊销，除非有明确 API 结果。

## 5. Git 执行安全

- Worker 不通过 `cmd.exe`/PowerShell/bash，不解析整条命令。
- executable 使用配置并验证的 `git.exe`，启动时记录版本和路径；版本变化重新健康检查。
- 参数按动作模板生成，分支/ref 使用 Git 校验，文件路径加 `--` 分隔。
- 禁止通过环境覆盖 `GIT_DIR`、`GIT_WORK_TREE`、`GIT_CONFIG_*`、hooks path 等改变边界；Worker 清理危险继承变量。
- 仓库级锁 + 超时；网络认证不得弹交互窗口造成后台挂死。
- 预检/批准/执行参数哈希一致；HEAD、Index/工作区关键状态按动作复核。
- Git 输出脱敏 remote 中的用户信息/Token 和疑似 secret。

## 6. 外部 HTTP 安全

- TLS 证书默认严格验证；公司自签 CA 通过受控信任配置，不提供“忽略证书”常驻开关。
- base URL 规范化并限制路径拼接；重定向到不同 host/scheme 时拒绝。
- 分离连接/读取/总超时；响应大小和 JSON 深度有限制。
- 429 使用 Retry-After，5xx 指数退避加抖动；401/403/业务 4xx 不重试。
- 供应商响应视为不可信：schema 校验、字符串长度限制、安全渲染。

## 7. AI 与隐私控制

- 默认 metadata-only 是不可由单次 prompt 关闭的策略。
- 发送前展示用途和数据类别，不显示秘密扫描命中原文。
- 适配器不支持工具执行；任何 tool call 输出一律拒绝/忽略。
- Provider base URL 应允许企业白名单；禁止本机、内网、云元数据 IP，除非管理员级配置明确且经过安全评审（首版建议不开放）。
- 记录供应商、模型、时间、用途、字段类别和哈希，满足审计但最小化留存。

## 8. 审计设计

必须审计：连接创建/测试/替换/撤销、仓库白名单、Git 预检/批准/逐项结果、导入提交、字段映射、证据人工决定、周报版本确认/提交/通知、绩效确认/导出、备份/恢复、留存清理。

审计条目不可由普通 UI 编辑/删除。内容是摘要和哈希，不是 debug dump。用户可导出脱敏审计；导出本身留审计。

## 9. 幂等、重试和断路器

### 9.1 分类

- 安全自动重试：只读 GET、分页读取、明确幂等的本地 upsert。
- 条件重试：带同一幂等键且供应商明确支持/可查询结果的写请求。
- 禁止自动重试：Git commit/push 等本地副作用结果未知、无法查询的钉钉创建日志。

### 9.2 断路器

按连接和能力维护 closed/open/half-open。连续网络/5xx 超阈值后短期开路，页面显示降级；认证错误直接 invalid，不用断路器掩盖。手动“测试连接”可发受控探测。

## 10. 作业恢复

作业状态：queued/running/succeeded/failed/cancelled/unknown/dead_letter。Worker 使用租约和心跳；进程重启回收过期租约：

- 只读任务可重排。
- 本地数据库尚未产生外部副作用的任务可重排。
- Git/钉钉写任务查操作记录和实际状态，进入 succeeded/failed/unknown/needs_review，不直接重跑。
- 超最大次数进入 dead letter，必须人工处理。

## 11. SQLite 可靠性

- 开启 WAL、foreign_keys、合理 busy_timeout；单写者短事务。
- 连接池规模符合 SQLite，不用大量并发写。
- 每日执行在线一致备份 API/受支持机制，不直接复制活跃 db/wal 文件组合。
- 周期执行 quick_check；备份定期恢复演练到隔离目录并校验 schema/关键计数。
- 磁盘空间低于阈值时停止导入/导出等增长操作，保留只读和清理建议；绝不静默删审计。

## 12. 备份与恢复

### 12.1 备份内容

数据库、非敏感应用配置、必要的版本模板和可选导出索引。保险箱秘密是否可备份取决于 Windows 机制；默认不把可解密秘密复制进普通备份。导出文件可配置是否纳入。

建议默认：每日 7 份、每周 4 份、每月 6 份，最终由企业策略确认。备份加校验哈希，成功/失败可见。

### 12.2 恢复流程

停服务 → 选择备份 → 验证哈希/schema/应用版本 → 备份当前状态 → 恢复到临时位置并完整性检查 → 原子切换 → 启动只读核对 → 恢复写模式。恢复后凭证引用失效时提示重新配置，不能因缺秘密导致数据库恢复失败。

## 13. 日志和可观测性

### 13.1 结构化事件

统一字段：timestamp、level、component、event、correlationId、operationId、target type/id、durationMs、outcome、errorCode。路径按策略可只显示仓库别名/路径哈希。

### 13.2 指标

- HTTP 请求耗时/错误（路由模板，不含 ID）。
- 作业队列深度、等待/执行时间、失败/重试。
- Jira/GitLab 同步读取/变更数、游标延迟。
- Git Worker 动作耗时、stale preview、needs review 数。
- 周报生成/确认/提交/通知成功率和 unknown。
- AI 调用耗时、拦截、解析失败、用量（不记录内容）。
- 数据库大小、备份年龄、磁盘余量。

首版可只在本机运维页展示，不必外发遥测。任何外部监控接入需单独授权。

### 13.3 健康检查

`liveness` 只表示进程可响应；`readiness` 检查 DB/迁移/Worker/实例租约，不要求所有外部平台健康。外部状态在 integration health 单独展示，避免 Jira 故障让整个本机 UI 不可用。

## 14. 性能与容量

基线：14 仓库、个人 Jira 任务和季度级元数据。控制：

- 仓库状态并发 2，单仓库串行写。
- GitLab/Jira 分页和字段白名单，批量 upsert。
- 列表读模型和索引，避免请求时 N+1 外部调用。
- AI/导出/同步用后台任务，不占 HTTP 长连接。
- 设定数据库/日志/导出/临时文件配额和清理策略。

实施阶段需以包含大仓库、长路径、中文文件名和千级任务的数据做基准；NFR 阈值见 01。

## 15. 安装、升级和回滚

- 发布包有版本、校验和、依赖/SBOM（实施要求）。
- 升级前兼容性检查和数据库备份；迁移成功后才切换版本。
- 应用二进制可回滚，但数据库只在 schema 向后兼容时直接回滚；否则使用升级前备份恢复流程。
- 设置页展示应用、schema、Git、外部能力版本，便于诊断。

## 16. 运行手册场景

必须形成可执行 runbook（实施阶段）：端口占用、DB locked/corrupt、磁盘不足、Git 凭证弹窗/超时、Jira 字段失效、GitLab 429、钉钉 unknown/重复风险、机器人签名失败、AI 数据拦截、备份失败、升级迁移失败。
