# 11 测试与验收设计

## 1. 质量策略

测试目标不是只证明“正常路径能点通”，而是证明：不会漏任务、不会越权执行 Git、不会重复提交正式日志、不会把空工时当零、不会把 AI 建议当事实、失败后能判断和恢复。所有关键业务状态机、合并规则和安全边界必须在外部系统不可用时仍可自动验证。

## 2. 测试层级

| 层级 | 重点 | 外部依赖 |
|---|---|---|
| 领域单元 | 状态转换、日期/工时、去重、评分、净化、幂等 | 无 |
| 适配器契约 | Git CLI 解析、GitLab/Jira 分页、钉钉/AI schema | stub/录制的脱敏响应 |
| 数据集成 | SQLite 约束、迁移、事务、游标、恢复 | 临时 DB |
| 组件集成 | API + Worker + fake servers + 测试仓库 | 本地隔离环境 |
| 端到端 | 浏览器关键流程、确认和错误展示 | 完整本机测试部署 |
| 企业联调 | 公司实例权限、字段、模板、频控 | 受控测试账号/群/项目 |
| 非功能 | 安全、性能、可靠性、备份恢复、可访问性 | 近真实数据规模 |

## 3. 测试数据和隔离

- Git 测试只使用临时目录下创建的本地/裸远端仓库，绝不指向 `D:\company` 真实仓库。
- 构造 clean/dirty/staged/untracked/conflict/detached/unborn、ahead/behind、非快进、hook 失败、长路径、中文/空格/前导短横线路径。
- GitLab/Jira 使用协议 stub 覆盖分页头、同时间戳任务、total 变化、空页、429、401/403、5xx、超时和 schema 漂移；企业联调使用最小权限测试资源。
- Excel 测试以已核验样表的只读副本和合成变体：1900/1904 日期、公式无缓存、G 空/H 0、半空父任务、非法日期、额外列、损坏 zip、超大表。
- 钉钉使用专用测试应用/群/模板，消息带显眼“测试”；生产群测试必须用户明确确认。
- AI 用 fake provider 验证数据边界；真实 provider 联调只发人工合成元数据。
- 测试日志和快照必须经过秘密扫描，fixture 不包含真实 Token/Webhook/客户数据。

## 4. 领域规则测试矩阵

### 4.1 Git

| 场景 | 预期 |
|---|---|
| 预检后 HEAD 改变 | 执行项为 stale_preview，未运行写命令 |
| Commit 预检后 Index 改变 | 拒绝执行并要求重预检 |
| Pull 非快进 | 预检阻断，不发生 merge/rebase |
| Push 远端领先 | 阻断；不生成 force 参数 |
| 批次 14 仓库中 2 失败 | 12 个结果保留成功，2 个有独立错误，批次 partial_failed |
| Stash apply 冲突 | needs_review，stash 不自动 drop |
| 分支名/路径注入字符 | 参数校验或安全参数数组处理，不能执行额外命令 |
| 白名单路径被 junction 替换 | identity/realpath 不一致，拒绝写 |
| 重复 approve 同 idempotency key | 返回同一 operation，不重复执行 |
| force/reset/raw shell API 输入 | schema 拒绝且 Worker 无可表达动作 |

### 4.2 Jira 同步

| 场景 | 预期 |
|---|---|
| 多任务相同 updated 跨页 | 全部入库，无遗漏/重复 |
| 第 3 页超时 | 整次失败，成功水位不推进 |
| 重叠窗口再次返回旧任务 | 内容哈希幂等，不新增重复历史 |
| total 在分页间变化/省略 | 依据实际页推进并安全结束 |
| 字段 ID 被删除/类型改变 | mapping_invalid，旧数据可读，水位不推进 |
| 任务不再由当前用户负责 | 增量不删除；全量核对后 out_of_scope |
| 无 changelog 的状态差异 | 记录观测区间，不伪造精确完成时间 |

### 4.3 Excel

| 场景 | 预期 |
|---|---|
| A/B 空且上一行父任务有效 | 同 sheet 继承父任务 |
| 首条工作行 A/B 空 | blocking，不能提交该行 |
| A 有值 B 空 | conflict，不自行猜名称 |
| 父容器 C/D 空 | 保存父上下文，不创建个人工作项 |
| C 有值 D 空 | 未分配 warning，不进入个人周报 |
| D 有值 C 空 | blocking |
| G 空、H 公式缓存 0 | hours/person-days 都为 null |
| G=0 | 明确零，与 null 区分 |
| F 为 WORKDAY 公式 | 读缓存日期和公式；不擅自重算 |
| Jira 有工时、Excel 不同 | 默认保留 Jira，显示冲突/来源 |
| 相同文件重复提交 | 命中哈希/幂等，不重复创建 |
| 系统测试表只有 A:G | 正确识别，父容器不报缺 H |

### 4.4 周报/钉钉/AI

| 场景 | 预期 |
|---|---|
| 没有问题 | 第五字段为“暂无” |
| 只有多个 Commit | 聚合成工作结果，不逐条复制 message |
| 工时为空 | 正文不显示 0 小时 |
| 人工编辑已确认版本 | 创建新版本并撤销可提交确认 |
| 重复点击正式提交 | 一个 delivery intent/外部日志 |
| 提交请求超时 | unknown，禁止盲重试，先查询/核对 |
| 日志成功、机器人失败 | partial delivery，只能重试通知 |
| 模板字段变化 | 提交阻断并要求重映射/重确认 |
| AI 输入含疑似 Token/diff | 净化拦截，不发送 |
| AI 输出引用不存在证据/改了工时 | 校验失败，回退规则版本 |
| AI 不可用 | 可生成规则草稿和人工编辑 |

### 4.5 绩效

| 场景 | 预期 |
|---|---|
| 只有 Commit 数量无成果关系 | 不自动产生高分或工时 |
| 相同证据支持两个候选 | 提示重复，用户决定合并/解释 |
| 指标权重不满足模板 | 禁止确认总分 |
| 各指标分数不同 | 分项和加权计算正确 |
| 取整前后差异 | 按模板规定阶段取整并可展开明细 |
| AI 建议生成 | 不填入用户分，不自动选成果 |
| 确认后改成果/分数 | 旧确认失效，历史导出保持 |
| Excel 公式结果与系统不同 | 导出失败并报告对账错误 |
| Word 长表格/中文 | 渲染无截断、乱码和不可读分页 |

## 5. 适配器契约测试

### 5.1 GitLab

- PRIVATE-TOKEN/授权头不出现在日志。
- project path 正确 URL 编码；大小写和 `.git` 处理。
- `Link rel=next`、`X-Next-Page`、无总数、大于一页均完整读取。
- 分支/Commit/MR/Pipeline/Tag/Release 字段缺失或新增时兼容。
- 401、403、404、429、5xx 分类；Retry-After 生效。
- 不请求 repository files/diff/job logs/variables。

### 5.2 Jira

- `/rest/api/2/myself/field/project/search` 的公司版本响应契约。
- POST search 的 fields/startAt/maxResults/JQL；服务端实际 page size 小于请求仍推进。
- PAT/OAuth 实际授权方式、TLS 和项目权限。
- 自定义字段多种数据形态和 unknown 状态保留。

### 5.3 钉钉

- 模板发现和字段类型/必填/限制。
- 日志创建、外部 ID、结果查询、接收范围、附件。
- 机器人 timestamp/sign/URL encoding、时钟偏差、消息上限和频控。
- 日志与机器人权限/失败相互独立。
- 企业联调结论固化为能力矩阵和 regression contract。

### 5.4 AI

- 三种协议的鉴权、base URL、模型、超时、usage、停止原因。
- 结构化输出正常/缺字段/非法 JSON/超长/拒绝。
- 供应商 401/403/429/5xx 和连接中断。
- provider 响应中的 HTML/Markdown 不能造成前端脚本执行。

## 6. API 与前端测试

- 统一错误结构、correlation ID、分页、ETag/If-Match。
- 状态机越级请求返回 409/422，不通过前端隐藏来“保护”。
- 所有幂等端点测试同 key 同 body、同 key 异 body、并发重复。
- 文件上传测试 MIME、扩展名、路径、zip bomb、大小、取消。
- 前端刷新/崩溃恢复 operation，部分结果保持。
- 键盘导航、焦点、状态非颜色唯一、表格标签和错误关联。
- 中文、Unicode、超长标题、空值和 14 仓库密集信息不破版。

## 7. 安全测试

1. localhost CSRF、恶意 Origin、Host/DNS rebinding、宽松 CORS。
2. Git 参数/路径/分支/Commit message 注入和环境变量继承。
3. repository junction/symlink 逃逸、上传路径穿越。
4. AI/GitLab/Jira base URL SSRF、重定向到内网/metadata。
5. XSS：外部任务标题、Commit、模型输出、错误文本。
6. Token/Webhook/Authorization 在 DB、日志、审计、响应、诊断包的秘密扫描。
7. DPAPI 当前用户隔离，以及 Docker AES-GCM 的明文不落盘、篡改/错误密钥拒绝、并发首启、撤销和替换。
8. 文件解析资源耗尽和恶意公式/外部链接。
9. 业务授权绕过：未确认版本提交、未批准 Git、通知含完整正文。
10. 依赖和发布物漏洞/SBOM/校验（编码及发布阶段）。

## 8. 可靠性与恢复测试

- API 在外部调用前/后、本地结果落库前崩溃的故障注入。
- 调度租约过期、重复 worker、进程重启、系统休眠/唤醒和时钟变化。
- SQLite busy、磁盘满、WAL、quick_check、备份期间写入。
- 每日备份生成、哈希验证、隔离恢复和凭证引用失效。
- 钉钉 unknown、Git timeout 后实际状态复核，证明不会自动重放写操作。
- 日志轮转和留存不会删除仍需审计的数据。

## 9. 性能基准

| 场景 | 数据规模 | 目标 |
|---|---|---|
| 仓库中心缓存首屏 | 14 仓库 | P95 ≤ 2 秒 |
| 本地状态刷新 | 14 个常规仓库 | 并发 2，页面持续有进度，无整体超时 |
| Jira 增量 | 1,000 任务、20 页、重复窗口 | 正确优先；目标 ≤ 60 秒（受实例影响单列） |
| 任务列表 | 10,000 本地记录 | P95 ≤ 2 秒分页返回 |
| 周报规则生成 | 500 任务/2,000 证据 | P95 ≤ 10 秒 |
| 季度候选 | 5,000 证据 | 可后台完成，页面可取消/恢复 |
| Excel 导入 | 10,000 行上限 | 无内存失控，行级错误可分页 |

企业外部 API 耗时与本机处理耗时分开报告，不能用网络慢掩盖 N+1 或低效数据库查询。

## 11. UAT 业务场景

1. 初次安装，发现并确认 14 仓库，配置 GitLab/Jira 身份。
2. Jira 正常：同步个人任务、确认字段和 Git 证据、生成并编辑周报。
3. Jira 暂停：查看 stale 缓存，导入真实三表 Excel，不覆盖 Jira 数据。
4. 跨仓创建任务分支：部分仓库预检阻断，其余批准并正确执行。
5. Commit 前 Index 被外部改变：系统拒绝旧预检。
6. 正式周报提交成功，机器人首次失败，随后只补发通知。
7. 正式提交超时未知：系统阻止重复，查询/人工核对后收敛。
8. AI 服务不可用：仍能完成周报和绩效材料。
9. 汇总季度成果，排除重复，映射不同指标/分数，公式对账并导出。
10. 重启/休眠/磁盘/外部 429 后作业和状态正确恢复。

## 12. 发布门禁

- P0/P1 缺陷为 0；危险命令、秘密泄漏、重复正式提交、同步漏数视为 P0。
- 所有 AC 有可复核证据；企业联调门通过。
- 真实样表导入回归通过且文件哈希未变化。
- 备份恢复演练成功。
- 安全测试无未接受高风险项。
- Excel/Word 视觉和公式 QA 通过。
- 运维 runbook、回滚和已知限制交付。
