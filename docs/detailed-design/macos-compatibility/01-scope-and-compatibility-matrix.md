# 01 范围、现状与兼容矩阵

## 1. 背景

Auto Work 当前核心业务多数由 TypeScript、Node.js、浏览器和标准 Git CLI 实现，具备跨平台基础；不能在 macOS 完整工作的原因主要是若干平台能力直接绑定 Windows，而不是全部业务不可移植。

本设计的目标是把这些阻塞点转换为显式的平台端口和能力状态，使 macOS 原生部署达到可安装、可操作、可诊断、可升级和可验收，而不是仅做到“源码能够启动”。

## 3. 需求定义

### MAC-REQ-001 平台能力发现

服务必须返回平台、架构、部署形态及原生能力状态。页面不得通过 User-Agent 猜测服务运行平台。

### MAC-REQ-002 本机用户身份

macOS 必须使用稳定的当前用户身份键建立或复用唯一 `UserProfile`。Windows 数据升级后必须继续关联原 `profileId`。

### MAC-REQ-003 原生目录选择

macOS 原生部署必须能从仓库配置页面打开系统文件夹选择窗口，返回经过规范化和权限校验的绝对目录；取消选择不得记为错误。

### MAC-REQ-004 Excel 导入可达

用户必须能从“任务与证据”页打开现有 Excel 导入工作台，并完成上传、预检、冲突处理、提交和结果刷新。

### MAC-REQ-005 Git 兼容

macOS 必须支持当前可见的仓库发现、状态刷新、分支查询、跨仓库分支创建和安全删除。已有受限 Git 引擎在 macOS 的预检和执行语义必须与 Windows 一致。

### MAC-REQ-006 季度制品下载

macOS 上的 Safari 和 Chrome 必须能够下载通过 QA 的 `.xlsx` 和 `.docx`，文件名、MIME、长度和哈希必须保持正确。

### MAC-REQ-007 钉钉桌面日志

没有钉钉开放接口权限时，macOS 用户在授予必要系统权限后必须能完成与 Windows 相同的公司、模板、字段和群校验，以及正式日志提交、截图证据和结果未知保护。

### MAC-REQ-008 安装与运维

必须提供用户级安装、启动、停止、升级和回滚流程，支持登录后启动，不要求 root 权限，不开放非回环监听。

### MAC-REQ-009 跨平台回归

增加 macOS 不能破坏 Windows 原生或 Linux Docker 的身份、凭据、Git、钉钉和文件行为。

## 5. 用户与运行场景

### 5.1 macOS 原生

用户安装发布包，配置仓库根目录后，由用户级 LaunchAgent 启动 API。浏览器访问 `127.0.0.1:3760`。目录选择器和钉钉桥接运行在同一登录图形会话。

### 5.2 macOS Docker Desktop

API 和 Web 运行在 Linux 容器，仓库根目录以 bind mount 映射到 `/repositories`。浏览器不能改变现有挂载；钉钉桥接运行在 macOS 宿主机，通过只包含一次性请求和响应的目录与容器通信。

### 5.3 Windows 回归

Windows 继续使用 SID、DPAPI、PowerShell 目录选择器和现有钉钉适配器。平台抽象只改变依赖选择方式，不改变提交状态机和安全策略。

## 7. 范围边界

### 7.1 本次包含

- macOS 原生服务和用户级运维脚本。
- macOS 目录选择器和平台能力端点。
- 本机身份中立化与安全数据迁移。
- Excel 导入入口接线。
- 现有 Git 功能的 macOS 验证。
- macOS 钉钉桌面完整自动提交。
- macOS 构建、签名、公证、CI 和 UAT。

### 7.2 本次不包含

- Git 批处理全功能页面。
- App Store、DMG 图形安装向导或自动更新服务。
- 多用户共享、远程访问、服务端集群和反向代理。
- Jira 通用写回、AI 工具调用或自动绩效评分。
- 将现有 Windows DPAPI 密文直接转换为 macOS 可解密密文。
