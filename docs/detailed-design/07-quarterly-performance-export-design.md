# 07 季度绩效与导出详细设计

## 1. 目标与原则

季度绩效模块把分散事实整理为可选成果池，帮助用户形成有证据的自评材料。它不把 Git 活跃度等同绩效，不自动决定最终分数，不自动向公司系统提交。所有聚类、AI 建议、人工筛选、评分和导出均保留版本和证据。

## 2. 季度定义与准备

- 默认自然季度 Q1～Q4，时区 Asia/Shanghai；允许创建自定义考核周期但名称和日期不可与已有周期混淆。
- 创建 review 后冻结周期定义，不直接修改；日期变化通过新 review 或显式重建并保留旧版。
- 收集前检查 Jira/GitLab/Git/周报最新同步时间、字段映射和身份别名。
- 数据过期时允许继续，但报告顶部显示数据完整性清单，确认和导出需用户知悉。

## 3. 成果候选收集

### 3.1 来源及纳入条件

| 来源 | 候选条件 | 不能推断 |
|---|---|---|
| Jira | 期间完成/关闭的个人任务；或有明确期间贡献的推进任务 | “updated 在季度内”不等于已完成 |
| 工时 | Jira/Excel 中有来源的实际/预估工时 | 工时高不等于价值高 |
| Commit | 当前用户确认别名、期间内、项目白名单 | 数量/行数不直接计分 |
| MR | 作者/参与及期间内创建、合并、评审贡献 | 打开 MR 不等于交付完成 |
| Pipeline/Release | 与确认 Commit/MR/任务相关，状态/发布事实明确 | 成功 Pipeline 不自动等于业务上线 |
| 周报 | 已确认版本中的成果段落 | 草稿不作为正式证据 |
| 人工 | 用户输入的会议、调研、协作、应急等 | 无证据时必须标人工陈述 |

所有时间边界使用 `[periodStart 00:00, nextPeriodStart 00:00)`，避免季度最后一天遗漏。

### 3.2 身份归属

Commit 作者通过已确认 Git name/email 别名匹配；MR/Jira 使用外部 account ID。未确认姓名只作为候选，不自动归属。共同成果允许标“个人贡献”，避免把整个团队成果全部归为个人。

## 4. 聚类与去重

### 4.1 确定性聚类

先按确认任务—证据关系、Jira 父任务、MR/Commit SHA、Release 关联聚类。一个证据可以支持多个成果，但必须说明不同贡献角度，系统提示重复引用。

### 4.2 语义建议

关键词/AI 只给出合并建议：候选集合、相似理由、可能的统一成果标题。用户选择合并、保持分开或部分拆分。AI 不能删除候选或自动选入最终材料。

### 4.3 成果结构

每项成果包含：

- 项目/业务域、成果标题、期间。
- 背景/目标（Situation/Objective）。
- 个人行动与职责边界（Action）。
- 可验证结果（Result）。
- 业务/质量/效率影响（Impact；没有量化证据时不虚构数字）。
- 状态：candidate/selected/excluded/needs_evidence。
- 主证据、辅助证据、人工说明。
- 关联考核指标和贡献说明。

## 5. 候选池交互

默认分组：待处理、已选、证据不足、已排除。支持按项目、月份、来源、状态、指标和证据完整性筛选。批量选择只改变选择状态，不自动映射指标或评分。

排除需要可选原因（重复、非本人、非成果、周期外、证据不足等）；保留以便重跑聚类时不重复出现。人工成果可随时添加，必须标来源并允许附本地链接/说明，但附件默认不送 AI。

## 6. 指标与评分模型

### 6.1 指标模板

没有公司模板时，系统只允许编辑成果和生成自评草稿，不生成“最终总分”。用户导入/配置指标模板后保存版本：指标 ID、名称、定义、权重、分数最小/最大、步长、是否必填、证据要求、排序、总分公式和取整规则。

权重校验：若公式为加权平均，启用项权重总和必须为 100%；若公司采用加分/扣分或其他公式，必须显式配置并有示例校验，不能暗中归一化。

### 6.2 成果到指标

成果可以映射多个指标，每条映射说明贡献角度；一个指标可有多个成果。系统提示没有成果的必填指标、没有指标的已选成果、单证据被过度复用等，但最终选择由用户决定。

### 6.3 AI 分数建议

AI 只基于选定成果、指标定义和许可证据摘要，为每个指标分别给出建议分、区间、理由、证据缺口和不确定性。不得默认所有分数相同，不得从 Commit 数量/行数推分。建议不写入用户分；用户必须逐项确认或录入。

### 6.4 最终计算

分项用户分需满足范围/步长。加权分使用未舍入原值计算；只在模板指定阶段取整。总分保存：模板版本、每项输入、权重、原始加权值、舍入值、公式表达和结果。任何分项/权重/公式变化使旧确认和导出失效。

## 7. 自评生成

### 7.1 生成结构

- 总体概述：季度职责和主要方向。
- 按指标或项目的核心成果：目标、行动、结果、影响、证据。
- 协作与能力成长：评审、支持、调研、AI 提效等。
- 问题和改进：事实化、不甩责。
- 下一周期计划：只使用用户选择的目标/未完事项。

### 7.2 事实约束

AI 输出的项目、任务、日期、工时、状态和量化结果必须能引用输入。没有量化数据时使用定性表述。用户修改产生新 narrative 版本；选择成果或分数变化时提示重新生成，但不覆盖人工版本。

## 8. 评审状态机

```text
draft
-> collecting
-> candidates_ready
-> selecting
-> scoring
-> narrative_ready
-> confirmed
-> exported
```

异常：`collection_failed / generation_failed / export_failed`。已 confirmed 后修改成果、指标、分数或正文，回到相应阶段并使确认失效；历史导出仍保留。

## 9. Excel 导出设计

### 9.1 工作簿结构

若公司提供模板，以模板为准并建立版本映射；无模板时标准导出至少包含：

1. `绩效自评`：周期、总体自评、确认时间、数据完整性说明。
2. `指标评分`：指标、定义、权重、AI 建议（明确标注）、用户分、理由、加权分、总分公式。
3. `成果明细`：项目、成果、行动、结果、影响、指标、状态、日期。
4. `证据索引`：成果 ID、证据类型、标题、外部 ID、URL、时间、可用性。
5. `数据说明`：来源同步时间、模板/公式/映射版本、AI 使用说明和免责声明。

数字/日期用真实单元格类型；总分和加权分由清晰公式计算，且导出前与系统计算结果对账。对编辑列设置数据验证或保护策略取决于模板要求；不隐藏 AI 建议来源。

### 9.2 公式准确性

导出生成后执行公式错误扫描、权重总和、分项范围、加权分和总分对账；发现差异则导出失败而不是交付错误文件。保存输入快照和文件 SHA-256。

## 10. Word 导出设计

默认结构：封面/基本信息、季度总结、按指标成果、自评分数表、问题与改进、下一步、证据附录、生成说明。使用标题样式、表格和页码，外部证据用可点击链接或清晰 ID。内容过长时分页保持标题与首段同行，表头跨页重复。

Word 正文以已确认 narrative 版本为准，不现场重新调用 AI。生成后渲染为 PDF/页面图片做版式 QA（实施阶段），确保无截断、孤行、表格溢出或乱码。

## 11. 导出幂等和文件管理

导出请求由 review ID + confirmed snapshot hash + format + template version 唯一确定。相同输入可返回已有有效文件；模板或内容变化生成新 artifact。文件放在受控 exports 目录，名称做安全规范化，例如 `2026-Q2-绩效自评-v3.xlsx`，实际唯一性由内部 ID 保证。

导出不等于提交。UI 只提供下载/打开目录，不提供发送邮件、上传公司系统或钉钉自动提交。

## 12. 数据完整性评分（非绩效分）

系统可计算材料完整性提示，必须与绩效分数视觉和语义隔离：来源新鲜度、已选成果有证据比例、必填指标覆盖、分数理由完整、未解决冲突数。它只帮助检查材料，不能进入总分公式。

## 13. 异常与恢复

- Jira/Git 同步部分失败：成果池标来源不完整，保留已收集候选；不把缺失视为零成果。
- AI 失败：仍可手工编辑或规则模板生成。
- 指标模板变化：旧 review 保留旧版本，新版本需用户迁移映射并重新确认。
- 导出失败：保留失败记录和诊断，不留下被当作成功的半成品。
- 证据链接失效：历史成果保留标题、外部 ID 和当时摘要，标不可用。

## 14. 验收重点

- 季度边界、身份归属和来源去重正确。
- 不以 Commit/行数直接评分或估工时。
- 用户可以逐项选择/排除并恢复，AI 不替用户选择。
- 指标分数允许不同，范围/权重/取整和总分完全符合模板。
- Excel 公式与系统结果一致，Word 版式验证通过。
- 任一最终材料只导出到本地，不自动对外提交。
