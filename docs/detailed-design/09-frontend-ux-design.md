# 09 前端信息架构与交互设计

> macOS 能力驱动 UI、系统权限卡片、Excel 导入入口和平台中立文案见 [macOS 原生能力与页面入口](./macos-compatibility/04-native-capabilities-and-ui-entry.md)及[API 与前端行为](./macos-compatibility/06-api-contracts-and-frontend-behavior.md)。

## 1. 设计目标

前端不是“一个按钮自动做完”的黑箱。它应让用户在 14 个仓库和多来源任务中快速定位状态，同时对危险写操作、数据过期、AI 建议和外部部分失败提供明确上下文。所有关键决策都能在确认前看见影响，在执行后看见逐项结果。

## 2. 全局信息架构

主导航：

1. 总览
2. 项目与仓库
3. Git 批次
4. 任务与证据
5. 周报
6. 季度绩效
7. 作业与审计
8. 设置与集成

顶栏持续显示：本机服务状态、Jira/GitLab/钉钉/AI 连接摘要、正在运行作业、数据最后更新时间。外部连接异常不使用全屏阻断；只在相关功能明确降级。

## 3. 通用交互规则

- 列表页面先展示缓存，后台刷新；每块都有 `as of` 时间和 stale 标识。
- 成功提示说明“完成了什么”，失败提示说明“哪一步、哪些对象、是否可能已产生结果、下一步”。
- 所有外部/批量写动作使用专用确认页或抽屉，不依赖浏览器简单 confirm。
- 危险确认不能只显示“确定吗”，必须显示动作、目标、参数、影响、警告、幂等/结果未知说明。
- 页面关闭不取消后台任务；用户可在作业中心继续查看。
- 空状态区分“尚未配置”“查询无结果”“同步失败”“筛选后为空”。
- AI 内容带统一徽标和数据来源入口；人工修改后标识来源变为“人工基于 AI 版本”。
- Token/Webhook 输入为一次性秘密输入，不提供复制/显示完整值功能。

## 4. 总览页

模块：

- 今日/本周行动：待确认 Git 批次、周报草稿/截止、失败任务、绩效待完成步骤。
- 仓库健康：14 个总数、dirty、behind、冲突、Pipeline failed、开放 MR。
- 任务摘要：进行中、blocked、逾期、本周完成、无证据。
- 同步新鲜度：Jira、GitLab、本地 Git、钉钉能力测试。
- 最近操作：只显示审计摘要，不显示敏感详情。

卡片点击进入已带筛选的目标页，不把所有功能堆成总览按钮。

## 5. 项目与仓库

### 5.1 仓库表格

默认列：项目/仓库、分支、工作区、ahead/behind、最近提交、Pipeline、MR、任务、刷新时间、操作。支持列设置、项目分组和状态筛选。状态颜色同时配图标/文字，不能只靠颜色。

每行展开区显示本地路径、remote、基线、GitLab 匹配、状态文件分类、相关任务和错误。路径可复制但不能在页面任意编辑为执行目标。

### 5.2 发现向导

步骤：扫描结果 → GitLab 候选 → 用户确认名称/项目/基线 → 白名单确认 → 结果。对 missing、worktree、路径逃逸、重复 remote 分别解释。一次向导可确认多个仓库，但每行必须有明确选择。

## 6. Git 批次体验

### 6.1 创建

先选择动作，再显示该动作专用表单，不提供“高级参数字符串”。仓库选择器展示当前分支、dirty、behind 和冲突，允许保存常用仓库集合但每次仍需预检。

### 6.2 预检页

上方：动作、参数、过期倒计时、可执行/警告/阻断数量。下方逐仓库卡片：当前状态、预计变化、展示命令、风险、阻断原因。阻断项不可勾选；warning 项需在批准区域逐类知悉。

批准按钮文案包含目标数，如“确认对 8 个仓库执行 Fetch”。Commit/Push 等更敏感动作可要求输入短确认词，但不能诱导复制命令。

### 6.3 执行结果

实时展示 queued/running/succeeded/stale/failed/needs review。批次结束保留逐仓库结果、操作前后 HEAD、错误和恢复建议。提供“仅对 stale 项重新预检”“仅重试明确安全的失败读动作”，不提供一键盲重试写操作。

## 7. 任务与证据

### 7.1 任务中心

主视图可在列表/父任务分组间切换。筛选：项目、统一/原始状态、Sprint、日期、来源、经办人匹配、证据状态、冲突。每项字段旁可查看来源标签，冲突使用并列对照。

任务详情页签：概览、来源与字段、状态观测、证据、周报引用、绩效引用。Jira 链接在外部打开，系统不提供编辑 Jira。

### 7.2 Excel 导入向导

步骤：选择文件 → 解析进度 → 工作表/列识别 → 行级预检 → 冲突处理 → 提交摘要。预检表固定显示工作表/行号、父任务、子任务、经办人、日期、工时、匹配、动作、问题。

用户可过滤 blocking/conflict/warning，点击定位单元格语义。修正表单明确“只修改本次导入，不会回写原 Excel”。提交前汇总 create/supplement/skip/conflict，blocking 未清零不可提交。

### 7.3 证据确认

左右对照任务和证据，展示匹配方法、命中 issue key/关键词、时间、项目和置信度理由。确认/拒绝均可撤销；AI 建议与确定性规则视觉区分。批量确认只允许相同高确定规则，不能批量采纳低置信 AI 建议而不查看。

## 8. 周报工作台

### 8.1 流程导航

页面顶端显示：数据收集 → 生成 → 编辑 → 确认 → 正式提交 → 群通知。每步展示时间、版本和负责人（本机用户）。异常步骤可展开，不把 partial delivery 显示为整个周报失败。

### 8.2 编辑器

左侧六字段，右侧来源/候选/版本历史。正文以安全纯文本/受限富文本编辑；报告块可展开证据。字段字数接近钉钉限制时提示。未确认 Git 候选默认不进入正式正文或明确标记。

顶部显示周期、填写日期、模板、接收范围和数据新鲜度。AI 操作是“整理/精简/按结果表达”等明确用途，调用前可查看将发送的数据类别。

### 8.3 确认与提交

确认页展示最终六字段只读预览、来源覆盖、未解决警告、附件、接收范围、模板版本。确认后页面锁定；编辑按钮明确会撤销当前确认。

正式提交按钮与“通知群”分开显示。日志成功后显示外部 ID/链接；通知失败只提供“重试通知”。unknown 状态突出显示“请勿重复提交”，提供查询/人工核对入口。

## 9. 季度绩效工作台

采用步骤条：周期与数据 → 候选池 → 成果编辑 → 指标映射 → 分数 → 自评 → 确认与导出。

- 候选池支持拖入已选区，但键盘也能完成；排除保存原因。
- 成果编辑采用背景/行动/结果/影响结构，旁边固定证据。
- 指标映射视图显示未覆盖必填项和一项成果多指标关系。
- 评分页同时显示指标定义、证据、AI 建议和用户分；用户分输入不由 AI 自动填入。
- 总分卡展示公式展开、权重校验和舍入说明。
- 导出页清晰标明“仅生成本地文件，不会提交公司”。

## 10. 设置与集成

分区：个人身份/别名、仓库根目录、GitLab、Jira 字段映射、钉钉日志模板、机器人、AI、工作日历、调度、备份与留存。

每个连接显示 healthy/degraded/invalid、上次测试和能力。替换凭证输入不回显旧值；撤销使用二次确认并说明哪些功能受影响。AI 设置展示默认允许/禁止的数据类别，禁止项不可通过普通提示词绕过。

## 11. 作业、审计与诊断

作业中心按运行中/失败/历史，显示进度、重试性、下一次重试和关联业务对象。审计页可按动作/对象/结果筛选，展示非敏感 before/after 摘要。诊断包生成前列出内容和排除项，用户明确确认。

## 12. 可访问性和国际化

- 键盘可达、焦点可见、表单 label/error 关联、对话框焦点圈定。
- 状态不只用颜色；对比度满足常见 WCAG AA 要求。
- 表格提供语义表头和可读替代摘要；长任务支持暂停自动滚动。
- 首版界面中文，但日期/时区/数字格式集中管理，外部 raw 状态不强行翻译丢语义。

## 13. 响应式和浏览器

主要面向 Windows 桌面现代 Chromium/Edge，最小有效宽度建议 1280；窄屏可查看但不承诺复杂批次/绩效编辑的完整移动体验。浏览器刷新后从服务端恢复草稿和 operation，不依赖内存状态。

## 14. 前端验收清单

- 用户始终知道看到的是缓存、刷新中还是最新数据。
- 所有业务写动作能在确认前看到目标与影响。
- 多仓库部分失败、日志/通知部分交付不会被单一 toast 掩盖。
- AI 内容、人工内容和事实来源可区分。
- 空工时与 0 工时、无问题与未填写、未提交与提交失败语义不同。
- 敏感字段从不回显、复制或出现在 URL/前端日志。
