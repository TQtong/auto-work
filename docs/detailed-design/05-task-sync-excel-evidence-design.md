# 05 任务同步、Excel 与证据详细设计

> Excel 导入组件接入“任务与证据”页、提交后的查询刷新和跨平台行为见 [macOS 原生能力与页面入口](./macos-compatibility/04-native-capabilities-and-ui-entry.md)。Excel 业务解析和来源规则仍以本篇为准。

## 1. 目标

建立统一的个人任务视图：Jira 为主事实，Excel 为 Jira 不可用时的兜底和缺失排期/工时补充；Git/GitLab 元数据作为工作证据。系统不写 Jira，不凭推测更改任务状态。

## 2. Jira 连接与字段发现

### 2.1 连接设置

用户只在本机设置页输入 base URL 和公司允许的认证材料。URL 必须是 HTTPS（显式开发例外不进入生产），禁止 URL 用户信息、片段和非允许 host 跳转。Token 写入本地保险箱后，页面只显示固定前后缀掩码和最近验证时间。

### 2.2 测试顺序

1. `GET /rest/api/2/myself`：确定身份和认证有效性。
2. `GET /rest/api/2/field`：发现标准/自定义字段。
3. `GET /rest/api/2/project`：确认可见项目。
4. `GET /rest/api/2/search`：按需求基线用小分页、字段白名单执行当前用户查询。
5. 额外探测 `POST /rest/api/2/search`：用于长 JQL 和后台同步；若公司实例不支持则适配器回退 GET，并严格控制 URL 长度。

测试结果区分 DNS/TLS/timeout、401、403、404、JQL/字段错误和成功但 0 项。只有身份和 search 成功才为 healthy；字段用途未映射为 `configuration_required`。

### 2.3 字段映射向导

按用途映射：计划开始日期、到期日、Sprint、父任务、原始/剩余/已耗工时、经办人、状态、优先级、标签、组件。每个候选展示 field ID、名称、schema type、样例值和出现率。用户确认后运行样例解析验证；保存不可变映射版本。

父子关系按兼容顺序：标准 parent → 自定义父任务字段 → issue link 配置。Sprint 允许单值、数组或供应商字符串，解析失败保留 raw 值并产生字段警告。

状态映射界面展示公司全部状态，要求映射到 `planned/in_progress/done/blocked/cancelled/other`。`other` 必须保留原状态；不得仅靠中文字符串硬编码。

## 3. 查询与增量同步

### 3.1 查询模板

- 任务中心默认交互查询：`assignee = currentUser() ORDER BY updated DESC`，保持需求基线的阅读顺序。
- 周报基础查询：`assignee = currentUser() AND updated >= startOfWeek() ORDER BY project, updated`；报告收集还应补查本周计划/到期但未更新的任务，不能只靠 updated 条件。
- 季度基础查询：`assignee = currentUser()` 加明确的 Asia/Shanghai 季度起止日期并按 project/updated 排序；完成成果还应结合 resolution/状态历史能力，不应把“季度内更新但未完成”全部视为成果。
- 增量同步传输查询：为可靠推进复合水位，使用 `updated ASC, key ASC` 的稳定顺序；这只影响后台读取次序，不改变任务中心默认的 updated DESC 展示。

JQL 使用参数化模板构建，用户高级自定义 JQL 单独校验，系统附加字段和分页，不字符串拼接未经处理的值。

### 3.2 防漏水位

仅以 `updated` 做单游标会遗漏同一时间戳的多条任务。详细策略：

1. 成功水位为 `lastUpdated + lastIssueKey`。
2. 下一次从 `lastUpdated - overlap` 查询，默认重叠 2 分钟。
3. 排序固定 `updated ASC, key ASC`，分页使用服务端实际返回大小。
4. 对 `(issue_key, updated, content_hash)` 幂等 upsert。
5. 全页完成才把水位推进到本次最大二元组。
6. Jira 返回 total 变化、空中间页或重复项都不能导致死循环；以实际页内容和 startAt 推进，设置最大页安全阈值。

### 3.3 观测和状态变化

search 默认只取需要字段。若公司权限允许 changelog，可为报告范围按需读取；否则状态事件仅记录前后两次观测间变化，标注 `observed_interval`，周报语言不能声称精确完成时刻。

任务本次不可见可能因为 JQL 范围、权限或分配变化。增量同步不删除；周期性全量个人核对成功后将未见项标为 `out_of_scope`，历史证据继续可访问。

## 4. Jira 合并语义

- 标题、类型、父子、状态、经办人、Jira 已有工时始终以最新 Jira 为准。
- Excel 计划开始/到期/工时只在 Jira 对应值为空时补充，记录每字段 provenance。
- 用户手工覆盖必须显式，保存 override 原因和有效期；Jira 后续出现值时提示冲突，不悄悄继续覆盖。
- description 默认不进入 AI；是否本地保存完整描述由企业策略决定，首版建议只保留必要摘要或不保存。

## 5. Excel 样表事实基线

已核验文件 `P_Manager_20260129_HQ_【gis功能】.xlsx`：

| 工作表 | 使用范围 | 结构特征 |
|---|---|---|
| 后端开发jira | A1:H11 | A:G 有标题，H 无标题；F 多行为 `WORKDAY(E, CEILING(G/8,1)-1)`，H 为 `G/8` |
| 前端开发jira | A1:H15 | H 为 `G/8`；多行日期/工时为空，H 计算/缓存可能为 0 |
| 系统测试jira | A1:G5 | 只有 A:G，当前为父任务容器行 |

标准列：A 父任务 id、B 父任务名称、C 子任务名称、D 经办人、E 开始日期、F 到期日、G 预估工时 h、H 人日（隐含）。样表中既有 Excel 序列值，也有公式/日期结果。

## 6. 导入管线

```mermaid
flowchart LR
    File["选择 XLSX"] --> Hash["大小/类型/哈希"]
    Hash --> Parse["只读解析工作簿"]
    Parse --> Detect["识别工作表和表头"]
    Detect --> Inherit["父任务继承"]
    Inherit --> Normalize["日期/工时/人员规范化"]
    Normalize --> Match["与 Jira/既有导入匹配"]
    Match --> Validate["错误和警告"]
    Validate --> Preview["逐行预检"]
    Preview --> Confirm["用户确认"]
    Confirm --> Commit["单事务写入"]
```

### 6.1 文件安全

- 只接受 `.xlsx` 且验证实际容器类型；拒绝宏文件、加密/损坏文件、超大小/超行列限制和 zip bomb 特征。
- 不执行宏、不加载外部链接、不刷新数据连接、不计算任意外部公式。
- 读取公式文本、缓存值和原始单元格类型；导入不依赖本机 Excel 自动化。
- 文件名只用于展示，服务器临时路径使用内部 ID；路径遍历无效。

### 6.2 工作表/表头识别

优先匹配三个精确名称；允许前后空格规范化但报告差异。表头通过语义别名映射，A:G 必需，H 可选且可无标题。发现额外列保留为 ignored 列并展示，不静默纳入任务字段。

### 6.3 行分类和继承

按工作表从第 2 行开始维护 `lastParentId/lastParentName`：

- A/B 都有值：更新当前父任务；若 ID 格式或名称异常，行错误。
- A/B 都空：继承最近有效父任务；此前没有父任务则 blocking error。
- 仅 A 或仅 B 有值：不自动拼接，标 conflict，用户可在预检中修正本次导入映射。
- C、D 都空：父任务容器；不创建个人子任务。
- C 有值而 D 空：可作为未分配任务导入，但默认不进入当前用户周报，给 warning。
- D 有值而 C 空：数据错误，不创建工作项。

父任务 ID 需匹配可配置 Jira key 格式，默认 `[A-Z][A-Z0-9_]+-[1-9][0-9]*`，但公司规则可放宽；不能硬编码 UTWIN。

### 6.4 日期解析

- 日期类型直接按工作簿日期系统转换；显式处理 1900/1904 date system。
- 数字序列转换后必须位于合理范围（默认 2000-01-01 至当前年 + 10）。
- ISO/常见本地日期字符串使用严格格式集合解析，歧义格式拒绝而非猜测。
- 公式单元格使用缓存结果；同时记录公式。若缓存缺失或错误，预检阻断/要求手工值。
- 只保存日期，不把午夜 UTC 转换造成日期前移。
- `end < start` 为 blocking；无开始但有到期允许，给 warning。

样表的 WORKDAY 未包含企业节假日表，所以导入按文件已有结果读取，不自行重算并覆盖。未来重算须配置法定节假日/调休日历版本。

### 6.5 工时与人日

- G 为空：`estimate_hours = null`、`person_days = null`，即使 H 的公式缓存为 0。
- G 为数值：必须 ≥ 0 且在合理上限内；0 是明确零工时，与空不同。
- H 有 `G/8` 或等价公式：作为校验值；实际人日按该导入采用的 `workday_hours` 版本计算。
- H 非公式且有值：比较 `G/8`，不一致为 warning/需用户选择，不自动覆盖 G。
- G 有值 H 空：按 8 小时/人日派生并标 derived。
- 所有派生保留原值、公式、换算参数和精度；显示可保留 2 位，不提前改变计算精度。

### 6.6 经办人匹配

样表出现姓名不代表当前用户。导入预检把 D 列姓名映射到已确认 identity alias；未匹配姓名作为其他人员或未知人员，不进入个人任务。首次映射必须由用户确认，不能写死任何样表姓名。

## 7. 匹配、去重和提交动作

### 7.1 匹配优先级

1. 子任务行自身存在明确 Jira issue key（未来扩展列）时精确匹配。
2. 父 issue key + 规范化子任务标题 + 经办人。
3. 父 issue key + 标题 + 日期的稳定指纹匹配历史 Excel 项。
4. 模糊标题仅产生候选，绝不自动合并。

当前样表只有父任务 issue key，因此不得把所有子任务错误地当成同一个 Jira issue。若 Jira 中能找到对应子任务，用户确认后链接；否则作为 Excel supplement task，父级引用 Jira 父任务。

### 7.2 Jira 主、Excel 补充

对明确匹配 Jira 的行生成逐字段合并预览：Jira 有值则 keep_jira；Jira 空、Excel 有值则 supplement；冲突并列展示并默认 keep_jira。提交不调用 Jira 写 API，只更新本地统一视图和来源观测。

### 7.3 重复文件/重复提交

相同 SHA-256 文件再次上传提示历史导入。用户可查看，不默认新建；同一预检的 commit 端点按幂等键返回原结果。行稳定指纹阻止重复工作项。

## 8. 预检错误分级

| 级别 | 含义 | 示例 |
|---|---|---|
| blocking | 该文件/行不能提交 | 损坏文件、无必需列、无父可继承、非法日期、D 有人但 C 空 |
| conflict | 需要用户选择 | A/B 半空、多个 Jira 候选、Jira 与 Excel 值冲突 |
| warning | 可按默认策略提交 | 未分配、日期不全、H 与 G/8 不一致、额外列 |
| info | 解释性 | 父容器跳过、字段由 Jira 保留、工时派生 |

UI 可筛选错误，显示 Excel 坐标、原值、规范化值、动作、理由和修正方式。修正只作用于本次导入预检，不回写源文件。

## 9. 证据采集与关联

### 9.1 证据范围

- branch：名称、当前/远端 SHA、仓库、活动区间。
- commit：SHA、标题/message、作者别名、时间、仓库、链接。
- MR：iid、标题、分支、状态、时间、链接。
- pipeline：ID、SHA/ref、状态、时间、链接。
- release/tag：发布成果候选。

不采集代码 diff；未关联 Commit 仍可进入周报候选，但必须标未确认。

### 9.2 确定性规则

issue key 提取使用已知 Jira project key 列表和边界匹配，避免普通单词/数字误识别。优先级：

1. branch 名 issue key，基础置信度 1.00。
2. Commit message issue key，0.98。
3. MR 标题 issue key，0.98。
4. MR source branch issue key，0.95。
5. Pipeline 通过 SHA 继承已确认 Commit 关系，0.95。

若一个证据包含多个 key，分别创建建议并提示一对多；不武断只取第一个。

### 9.3 关键词和 AI 建议

关键词规则基于同项目、时间窗口、标题分词和父任务上下文，置信度上限 0.79，必须人工确认。AI 只接收净化元数据和候选集合，输出候选 ID、理由和置信度，不能创造不存在的证据或任务；AI 建议上限同样低于确定性 issue-key 规则。

### 9.4 人工确认和生命周期

- 用户可确认、拒绝、撤销；操作留审计。
- 来源内容变化（如分支重命名、MR 标题变化）重新计算，已确认关系不自动删除，但标 `needs_revalidation`。
- 源对象删除/不可见时关系保留，证据标 unavailable。
- 拒绝关系在规则版本和内容哈希未变化时抑制重复建议。

## 10. 任务中心读模型

页面按状态、项目、父任务、Sprint、日期、来源和证据完整性筛选。每项显示字段来源标签（Jira/Excel/人工）、上次同步、状态映射、工时、证据数量和冲突。任务详情提供来源对照、状态观测、证据时间线和周报/绩效引用，但不提供 Jira 编辑按钮。

## 11. 降级与恢复

- Jira 不可用：展示缓存和过期时间，允许 Excel 预检/导入；不得把 Jira 错误自动切换为 Excel 覆盖。
- 字段被管理员删除/改类型：同步进入 mapping_invalid，旧数据可读，要求重做映射后再推进水位。
- 分页中断：不推进水位，重试整次重叠查询，upsert 保证不重复。
- Excel 解析失败：保留文件哈希和失败摘要，不保留敏感原文件副本。
- 证据源暂不可用：已有关系继续可见并标 stale，不影响报告历史版本。

## 12. 验收重点

- Jira Token 成功、失效、权限不足和字段异常可区分。
- 同一 updated 时间戳跨分页不漏任务，失败不推进游标。
- 三个样表全部识别；后端父继承、前端空工时、测试父容器均符合规则。
- G 空/H 公式为 0 时最终工时、人日仍为 null。
- Jira 主字段不被 Excel 覆盖，补充字段来源可追踪。
- 任务与 Git 证据的自动、建议、确认、拒绝和失效都可解释。
